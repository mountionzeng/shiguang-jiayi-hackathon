# 拾光家忆

开发前请先阅读 [工作环境与部署说明](docs/WORKSPACE.md)。

> 写下我走过的一生，也珍藏我们共同经历的家。

**拾光家忆是 Drinking Time 的微信小程序手机端。** 在手机上随时聊一段、记下记忆、整理成故事；想在电脑上接着做时，选好故事、生成一次性电脑登录码，就能在同一微信主体的 Drinking Time 账号里继续制作。

`#shenicest-fission` · 本项目起源于黑客松软件赛道的微信小程序文字 MVP（参赛期说明见下文）

## 作品简介

拾光家忆是一款面向不同年龄人生主角及其亲友的文字记忆工具。它不要求用户在开口前判断这段话“属于个人还是家庭”，而是先让 AI 安静听完，再慢慢整理：

- **人生之书**是我亲口讲述的内容视图：一个人可以有很多具体故事，也可以保留暂时无法归类的片段。
- **记忆之家**是我与亲友彼此授权阅读的内容视图：相关人物和阅读权限分开设置，每段故事的权限都可以不同。

本次黑客松版本聚焦一条可演示的文字闭环：

1. 首页以当前用户的水彩故事封面为最大主体，下方用一对等权图案按钮进入“人生之书／记忆之家”，并保留轻量“开始聊聊”、最近故事和“继续聊”；
2. 对话阶段只追问人物、时间、地点、经过和感受，不预设内容去向；
3. 聊完后可以把内容留作“未整理片段”，也可以归入已有故事或创建新故事；
4. “这段和谁有关”只用于整理，“谁可以看”才授予阅读权，两者互不替代；
5. 一段内容可以授权给多位亲友，未选择任何人时默认仅自己可见；
6. 记忆之家只展示当前身份获准阅读、或本人主动分享出去的故事，并兼容旧版已确认家庭记忆。

故事始终归讲述者本人；定向分享只增加阅读权，不会把故事变成接收者的人生之书素材。旧版家庭投稿仍保留确认流程与原有数据语义。

## 当前实现边界

本仓库首先交付可在微信开发者工具中运行的单设备演示闭环。真实微信身份、跨设备家庭邀请、云数据库持久化和正式内容审核仍是后续工作，演示时不会把这些能力描述成已经完成。

当云函数尚未配置 AI 密钥时，应用会使用明确标注的“本地演示草稿”模式：它只按当前用户亲自讲述的个人片段整理文字，不冒充 AI 生成，也不会补造事实。

内容边界在当前单设备演示中由领域层统一执行：新记录默认归讲述者所有，故事名、相关亲友和阅读名单分别保存；阅读名单支持多人，异常类型会失败关闭。未发出的输入在用户离开时也会先存为仅自己可见的未整理片段。旧缓存中没有作用域的片段仍按旧版家庭记忆处理，避免误入个人书。正式多人版本仍需通过微信身份、云端访问控制和删除撤回来执行同一规则。

当前身份仍由本地演示数据决定，不代表已经打通真实微信身份或跨设备家庭空间。

## 本地运行

1. 安装依赖：`npm install`
2. 类型与测试检查：`npm run check`
3. 在微信开发者工具中导入仓库根目录
4. 当前企业小程序 AppID 为 `wx86ae3e9d507ce52d`；使用微信开发者工具的成员需先由管理员添加为该小程序的开发者
5. 新账号使用独立的免费开发环境 `cloud1-d5ghzk30ve609f544`，不会回退连接旧账号环境
6. 新环境已部署五个基础函数；先用 `npm run deploy:wechat:preview` 核对安全默认清单，再按 `deploy/wechat-cloud.manifest.json` 补齐 42 个集合、索引、规则、超时、配置后启用的函数和服务端环境变量。当前 `CLOUD_AI_RELEASE_READY = false`，在函数、密钥、产品权限、配额、计费和安全路由验证完成前，真机不会调用在线 AI。实时进度见[微信小程序换账号迁移手册](docs/wechat-account-migration-runbook.md)

## AI 云函数环境变量

- `AI_API_KEY`：模型服务密钥，只能配置在云函数服务端
- `AI_BASE_URL`：OpenAI-compatible API 根地址
- `AI_MODEL`：文本模型名称

任何密钥都不得写入小程序代码或提交到 GitHub。

## 演示路径

统一讲述路径：`首页 → 开始聊聊／继续聊 → AI 追问 → 整理原话 → 未整理片段／具体故事 → 相关亲友 → 阅读权限 → 保存`

个人阅读路径：`首页 → 人生之书 → 阅读自己的故事与书稿 → 退出回首页`

共同阅读路径：`首页 → 记忆之家 → 阅读获准查看的亲友故事 → 退出回首页`
