# 拾光家忆：把「故事」做成真正的记录（问题四 · 方案稿）

状态：**方案稿，等用户确认后才写代码。** 分支 `feat/story-records`（基于 main d83f1ed）。
范围：问题四＝故事的数据与逻辑。页面怎么呈现归问题八；邀请与权限归问题三；图片归问题五。

## 用户已经定下的

1. 书就是故事。左下角「人生之书」＝所有故事的目录；首页书封＝顶部选中的那个故事。
2. 一个故事一个群：每个故事自己定主人公（任何人）、自己拉人；主笔永远是本账号。
3. 没有讲述人：这台手机上讲的都记在账号主人名下。
4. 记忆分「还没写进书 / 已经写进书」；一段记忆可以放进多个故事。**同一个故事里，一段记忆也可以放进好几章**（2026-09-14 定，取代问题二「一条记忆只在一章」）。
5. 「写没写进」由故事章节的引用推导出来，不存在记忆身上。

## 现在的问题

故事目前不是记录，是每次打开时临时算出来的（`services/storyShelf.ts`）：同一个故事名的记忆算一个故事，每个档案整理过的书稿算一个故事，同名的合成一项。它的编号是 `story:故事名` 或 `manuscript:档案id`，于是：

- 改名、或者书稿和同名记忆合并时，编号会变；挂在编号上的东西（最近删除、发到电脑端、首页当前故事、以后的邀请和封面）会对不上。
- 一段记忆只有一个 `storyTitle`，放不进第二个故事。
- 书稿版本按「档案」存，不按故事存；故事没有主人公。

## 目标结构

```
人（family_members）          记忆库（memories，原话不改）
        \                          /
         主人公[]              素材 memoryIds[]
              \                  /
               故事（stories，新）──── 版本历史（biography_drafts，按故事）
                                            └─ 每个版本 = 章节[]（每章：稳定 id、章名、memoryIds[]、图文、底图）
人生之书 = 所有没删除的故事；首页书封 = 选中的那一个
```

## 数据对象

### 故事 Story（新集合 `stories`，文档 id `${familyId}_${storyId}`）

| 字段 | 说明 |
|---|---|
| `id` | 稳定编号，如 `story-lx3k9f-a8b2c4d1`；改名、合并书稿都不变 |
| `familyId` | 所属账号空间（主笔＝这个账号，不另存） |
| `title` | 故事名，最多 40 字，可以改；同一账号内不重名（去掉首尾空格后比较，不含已删除的故事） |
| `protagonistMemberIds` | 主人公（名单上的人 id，0..n） |
| `memoryIds` | 这个故事的素材：属于这个故事的全部记忆，不论写没写进章节；一段记忆可在多个故事 |
| `createdAt` / `updatedAt` | 时间；人生之书按「最近动过」排序，取故事记录、素材记忆、最新版本里最晚的时间 |
| `deletedAt?` | 放进「最近删除」；恢复就清掉。取代现在 `families.deletedStories` 按名字记的做法 |
| `coverImageId?` | 预留给问题五的封面 |
| `legacy?` | 迁移来源：`{ memberId?: string; storyTitle?: string }`，只读，方便回溯和旧客户端兼容 |

### 版本 ManuscriptRevision（仍在 `biography_drafts`，`draftType: "manuscript-revision"`）

- 新增 `storyId`。以后每次保存只给这一个故事存一版，其他故事不受影响。
- 保留 `memberId`：迁移来的故事继续写原档案 id，旧客户端仍能看到最新书稿；新建的故事写 `story:<storyId>`，旧客户端按档案查不到它，不会误改。
- 恢复历史版本＝另存一个新版本；历史版本一律不改写、不删除。

### 章节 ManuscriptChapter（字段不变）

- `id` 在各版本之间不变；上移下移不变；删除只影响之后的版本。以后做合并：保留前一章 id，并提示被合并那章的底图会丢；拆分：前半段保留原 id。
- **规则改变**：`memoryIds` 不再要求一段记忆只在一章。「放进这一章」只加进这一章，不从别章移走；「移出这一章」只从这一章去掉。
- `backdropImageId?`（问题五已加）跟着章节进版本。

### 记忆 MemoryContribution（不改）

- `storyTitle` 保留为旧字段，不再作为「属于哪个故事」的依据；聊天存进某个故事时仍顺手写上故事名，旧客户端照旧能分组。
- 「写进了哪本书哪一章」由所有未删除故事的当前版本推导（问题三的 `memoryPlacements` 换成按故事算）。

## 迁移：先只在内存里算，不写库

打开小程序时，从现有数据算出故事列表（和现在的 storyShelf 同一套规则），但给每个故事一个**由来源决定的固定 id**：

- 每个档案的书稿 → 一个故事：id `story-m-<档案id>`，名字＝书名，素材＝各章用到的记忆 ＋ 同名故事名的记忆，`legacy.memberId`＝档案 id，版本仍读原来按档案存的那些。
- 其余每个故事名 → 一个故事：id `story-t-<故事名摘要>`，素材＝这些记忆，还没有章节。
- 现在的「最近删除」（按 key/名字记）→ 对应故事带上 `deletedAt`。
- 首页记住的当前故事（按名字）→ 换成对应的 id。

只有当用户**第一次改动某个故事**（改名、定主人公、放记忆、整理、删除）时，才把这一个故事写进 `stories`。id 是固定的，重复打开、重试都不会多出故事。

- 不改任何记忆、不改任何历史版本、不删 `families.deletedStories`。
- 回退：旧客户端不认识 `stories`，照原样工作；删掉 `stories` 集合，新客户端也回到按名字算的样子。

## 各处怎么接

| 地方 | 现在 | 以后 |
|---|---|---|
| 人生之书 / 首页书封 / 换一个故事聊 | `story:名字` key，按名字记当前故事 | storyId；当前故事存 id |
| 聊天存进故事 | 写 `storyTitle` | 加进故事的 `memoryIds`（同时写 `storyTitle` 兼容） |
| 书稿页 | 按「当前档案」读版本 | 按 storyId 读版本（迁移故事兼读 `legacy.memberId`） |
| 最近删除 / 恢复 | families 上按 key/名字 | 故事自己的 `deletedAt` |
| 发到电脑端快照 | storyShelf key | storyId ＋ 这个故事的素材 ＋ 当前版本章节 |
| 记忆「写进了哪里」 | 按档案的当前书稿 | 按故事的当前版本 |

页面文字和布局不在本方案内；只要换了数据来源导致显示变化，先告诉问题八。
