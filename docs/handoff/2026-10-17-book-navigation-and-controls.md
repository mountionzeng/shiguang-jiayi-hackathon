## 和本交接不一样的地方（按钮取舍建议）

| 当前按钮 | 代码职责 | 建议 |
| --- | --- | --- |
| 目录 | onBack → backToContents；有正文修改时先 finishEditing，保存失败保留当前页 | 单独保留，作为固定导航；不能与文字生成合并 |
| 照片 | 相册/相机导入；生成插图、底图、封面 | 保留一个“图片”入口，把“更多 → 给本章配图”的图片库能力也归入其中，保留各图片用途 |
| 新建章 | createChapter，新建章节版本 | 从正文工具栏移到“更多”；目录里的“新建章节”继续保留 |
| 保存 | saveEdits，收集原生编辑器正文、校验、写入版本，保存回执核对 | 保留显式保存。返回已有自动保存，不能因此把云端失败当成功或删掉用户主动重试入口 |
| 更多 | 邀请/权限、公开故事卡、选段发送、记忆、顺序、删除、历史、整章整理、图片库、有声书 | 保留。进一步整理为菜单分组；整章整理不能混同于只处理本次输入的小忆整理 |
| 小忆头像 | 在正文内读取选区或本章上下文并展开面板 | 保留入口；面板已展开时可隐藏重复头像 |
| 关掉 | resetXiaoyiPanel；会清空本轮问答、输入、写作要求及生成草稿 | 可改为“收起”图标，但必须同时改成保留本章对话与输入；不能只换文案，继续静默清空 |
| 问我一个问题 | 结合当前章节/选区、本次输入与问答追问；不会写正文 | 保留独立入口，避免与使用文字混淆 |
| 写成一段 | compose：将本次素材成文，可以参考正文上下文与写作要求，先展示可编辑草稿 | 与下两项统一到“使用这段话”菜单，但保留明确的“写成一段”选项，不能由模型猜测模式 |
| 整理原话 | polish：轻整理本次输入；避免重新生成/重复旧正文，先展示可编辑草稿 | 同上，保留“轻整理”选项；语义不同于成文 |
| 就用我的原话 | 不调用文字整理，原样生成本章待确认插入 | 同上，保留“原话保留”选项；不强迫使用 AI |
| 看看这一章的记忆 | 打开本章记忆面板；不调用 AI、不生成正文 | 与“更多 → 本章记忆”共用已有能力，可保留为小忆标题区的轻量“本章记忆”入口 |

建议常驻布局：顶部“目录 / 图片 / 保存 / 更多”；小忆中保留“问我一个问题 / 使用这段话”，本章记忆与收起放标题区。写作要求折叠为可选设置；输入内容保留。

功能边界不变：轻整理、成文、原话是三个明确选项；AI 结果可编辑；放入待确认修改后由用户决定是否采用，不能让“使用这段话”直接覆写正文。原需求要求常驻的原话/整理选择改为菜单会多一次点击，需要用户取舍。

代码核对能说明按钮连到什么功能，不能代替真实 AI、相册、分享或双账号权限验收。邀请仍受未部署后端及未授权开关限制。
