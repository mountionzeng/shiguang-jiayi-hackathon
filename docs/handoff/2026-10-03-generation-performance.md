日期：2026-10-03。工作树：`.worktrees/codex/restore-approved-ui-20260930`。起始提交 `a61bbd4`，保留已确认界面与本次小忆输入修复；主目录 personal-memory 的未提交内容未改动。

## 根因与改动

| 环节 | 原行为 | 修复后 |
| --- | --- | --- |
| 章节图片启动 | submit 后整房读取、图片列表读取，再固定等 3 秒才 status 触发生成 | 直接使用 submit 返回的任务，下一个事件循环即发起 status，省去两次读取和固定等待 |
| 封面启动 | submit 后重取封面来源、图片列表，再固定等 4 秒 | 使用返回任务直接调度，不重取来源和列表 |
| 多张图片任务 | 串行等待每次可能数十秒的 status，重新进入可重叠 | 每页最多两路，同页轮询只允许一轮在途，离开后不启动余下批次，不更新卸载页 |
| 状态刷新 | 完成后重新读整房或封面来源 | 只刷新图片列表；真正重新进入页面、设置底图/封面仍取新状态 |
| 图片已存储后的美观检查 | 同一次请求等待视觉模型最多 12 秒，才返回图片 | 已有 sweep 后台任务执行美观检查，图片先返回；平台审核仍按原流程送审，页面随后更新状态 |
| 整理记忆 | 按家庭分页扫描全部 memories，再找一个 ID | 标准 ID 直接读取一个文档；兼容历史非标准 ID 的回退扫描保留 |
| 正文生成素材 | 扫描家庭全部记忆后筛选至多 20 条 | 单条直接读，多条一次按主键集合查询；按请求顺序返回，权限/删除/个人范围/故事来源检查保留 |
| Node 16 网络 | 默认每次重新建连，完成请求不释放取消监听 | 四个 AI 云函数使用有上限的 keep-alive 连接池，完成后清除监听；不自动重发付费请求 |

本次删除了生成前无效刷新和前台等待美观检查的代码，未按文件数量批量清理。旧数据兼容读取、单独部署的云函数内网络适配文件仍有实际用途。

## 架构判断

目前应优先减少串行网络往返和前台必须等待的工作，不需要重新拆分一套服务。图片已有持久任务 ID、原子 claim、保存结果链接和后台 sweep，应继续围绕这套机制处理重试；禁止超时后自动重新付费生成。文章继续先保留原话，再给生成结果；权限、来源版本冲突和明确同意不应当作冗余代码删除。

后续若实测仍慢，依次区分：云端输入读取/审核、供应商生成、结果存储/审核。文字的真实流式返回属于接口与交互改变，需要独立设计；本次未换模型、未降低画质、未丢弃上下文，也不声称模型推理速度已经改善。
