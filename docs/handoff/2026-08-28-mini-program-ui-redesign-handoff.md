# 拾光：微信小程序前端重设计交接

## 任务结论

请在本仓库中重设计“拾光”原生微信小程序前端。产品不再从营销入口或公开家庭群聊出发，而是围绕“一位老人的人生之书”：全家看到同一个问题、各自接受采访、老人确认原始事实，确认且家庭可见的片段进入家庭时间线，再组合成有来源的传记章节。

产品需求的权威文档是：

- `docs/brainstorms/2026-08-28-shared-elder-life-book-redesign-requirements.md`

开始前完整阅读该文档。本交接负责把需求映射到现有仓库、队友原型和微信小程序实现边界；若两者冲突，以需求文档为准。

## 仓库与安全边界

- 只操作独立黑客松仓库，不修改 sibling 项目 `drinking-time-local`。
- 技术栈是原生微信小程序：WXML、WXSS、TypeScript，不是 React、H5 或网页套壳。
- 当前 AppID：`wx6be512f0fe129b62`。
- 开始前运行 `git status --short --branch`，从最新 `main` 新建 `codex/redesign-mini-program-ui`。
- 不重写现有 Git 历史，不覆盖其他人的未提交工作。

## 必须先看的队友原型

三个队友原型已原样保存在：

- `docs/references/team-prototypes/人生之书页面布局.html`
- `docs/references/team-prototypes/人生之书跳转逻辑.html`
- `docs/references/team-prototypes/记忆之家页面.html`
- 来源与校验说明：`docs/references/team-prototypes/README.md`

不要把 HTML 直接嵌入小程序，也不要把它们当作可运行代码。应复用其中的信息架构、页面状态和跳转思路，再用原生小程序重新实现。

## 队友成果的保留与适配

| 队友原型 | 处理方式 | 新版含义 |
|---|---|---|
| 屏 01：有内容首页 | 保留骨架 | 某位老人的人生之书、共享问题、确认片段和章节进度 |
| 屏 02：空首页 | 保留 | 引导全家完成第一段回忆采访 |
| 屏 03：双选写入面板 | 改造 | 中央加号直接进入单一“回忆采访”，不再选择随手记／回忆录 |
| 屏 04、05：两类 AI 对话 | 合并 | 一套独立采访页，AI 每次只追问一个方向 |
| 屏 06、07：两类叙事生成 | 合并 | 传记章节草稿，展示来源数量和待复核标记 |
| 屏 08：记忆详情 | 保留思路 | 查看确认片段或章节详情及来源 |
| 屏 09：长按菜单 | 当前暂缓 | 老人可发现性不足，必要操作优先使用明确按钮或更多菜单 |

新增的“记忆之家页面”原型按以下方式吸收：

| 队友原型 | 处理方式 | 新版含义 |
|---|---|---|
| 屏 01、04：未创建／已创建无内容 | 保留 | 区分未建立家庭空间、已建立但尚无合格公开片段 |
| 屏 02、03：全部时间线／成员筛选 | 重点复用 | 作为记忆之家主结构，只展示“老人已确认 + 家庭可见”的片段 |
| 屏 05、06：他人／本人详情 | 保留骨架 | 展示贡献者、发生时间、确认状态与来源；本人可撤销家庭可见 |
| 屏 07、08：更多操作 | 收敛 | 复制、转发、举报和删除按角色与真实能力显示，不使用难发现的长按入口 |
| 屏 09、10：创建记忆之家 | 后续接入 | 黑客松阶段可保留页面骨架，不得伪装真实跨设备家庭已建立 |
| 屏 11、12：发送／接受邀请 | 路径参考 | 保留文案、成员预览与权限说明；真实微信邀请未完成时显示明确演示状态 |

适配时必须统一以下语义：

- 原型中的“随手记／回忆录”统一为“回忆片段”或“传记章节”，入口仍只有“回忆采访”。
- 记忆之家时间线不得出现待确认、拒绝、冲突或私密投稿。
- “取消分享／从记忆之家删除”默认只撤销家庭可见状态；原始内容继续保留在人生之书，除非本人另行明确删除。
- 点亮、留言和举报属于次优先级，不得挤占采访、老人确认、来源查看和阅读闭环。
- 保留成员横向筛选、时间轴卡片和详情页信息层级，但使用新版明亮国画配色与老人友好的字号和触控尺寸。

封面原有四条点击关系也继续利用：

- 点击整张书封面：进入传记章节与阅读页。
- 点击“回忆片段”：进入已确认、家庭可见的片段列表。
- 点击“待确认”：老人进入确认页；家人进入自己投稿的等待状态。
- 点击“参与家人”：进入记忆之家时间线与成员视图。

## 新版页面结构

建议在保留现有四条业务链路的基础上形成五个主要页面：

1. 人生之书首页：共享书封面、进度、今日问题、最近确认片段。
2. 记忆之家：确认后公开的家庭时间线、成员与参与进度。
3. 回忆采访：每位成员独立的 AI 对话与可见范围选择。
4. 老人确认：一次一条的事实核对。
5. 章节阅读：章节正文、草稿标记、来源数量与来源展开。

现有页面可按以下方向演进：

- `miniprogram/pages/index/`：改成人生之书首页。
- `miniprogram/pages/room/`：改成记忆之家公开时间线。
- 新增独立采访页面，承接中央加号和今日问题入口。
- `miniprogram/pages/review/`：保留为老人确认页并改成一次聚焦一条。
- `miniprogram/pages/book/`：改成章节阅读与来源查看。

路由和底部导航的具体方案在实现前结合原生 tabBar、custom-tab-bar 和当前页面栈评估；不能为了复刻网页胶囊而破坏微信返回语义或安全区。

## 必须修正的现有行为

本次方向确认产生了一项真实业务变化，不能只在 WXML 中隐藏：

- 当前家庭可见投稿在待确认阶段可能被其他家人看到。
- 新要求是：任何投稿在老人确认前只对投稿者和老人可见。
- 只有“确认 + 家庭可见”才进入其他家人的视图、家庭时间线、章节和模型请求。
- 私密投稿确认后仍保持私密，不能进入公开时间线、章节或模型请求。

因此需要同步更新领域筛选逻辑与测试。不得只做前端条件渲染，否则其他入口仍可能泄漏待确认内容。

以下规则继续保留：

1. 只有老人角色可以确认事实。
2. 待确认、拒绝和冲突内容不进入正式来源。
3. 私密投稿只对投稿者与老人可见。
4. 生成期间来源变化时丢弃旧结果。
5. 云 AI 默认关闭；本地降级不得冒充 AI。
6. 未完成的邀请、微信身份和跨设备能力不得伪装成已实现。

## 视觉方向

### 品牌意象

Logo 使用原创“双鸟相伴”符号：两只抽象小鸟轻轻相向或前后依偎，表达陪伴、亲情、两代人的连接与共同回忆。参考的是意象和气质，不复制用户提供参考图的鸟形、构图、签名或水印。

Logo 需要满足：

- 小程序头像和导航级尺寸仍能识别。
- 轮廓简洁，减少细碎彩铅纹理。
- 图形标与中文名称分开输出。
- 不把整张封面插画缩小充当 Logo。
- 输出透明背景版本、浅色背景版本和单色备用版本。

### 界面气质

视觉关键词：现代国画、朦胧彩铅、点彩颗粒、渐变色、大面积留白、极简、抽象概括、轻微动态模糊／弥散。

建议颜色角色：

- 宣纸白：全局背景和长文阅读底色。
- 深墨绿：正文、标题和主要操作，保证对比度。
- 玉石绿：已确认、完成状态和主要品牌色。
- 湖水蓝：封面氛围与家庭共享区域。
- 杏黄：今日问题、提示和温暖记忆。
- 珊瑚红：主要行动、提醒和少量情感强调。

颜色应比旧版鲜明，但不能把低饱和浅色直接用于小字号正文。状态除了颜色还必须有图标或文字。

### 国画材质的使用范围

适合使用：

- 人生之书封面。
- 首页顶部氛围区。
- 空状态插花。
- 章节开头和段落间极少量插花。
- 页面切换或加载时很轻的弥散过渡。

不适合使用：

- 聊天气泡背后的高噪声纹理。
- 老人确认按钮与事实原文背景。
- 长篇正文整页铺彩色图片。
- 影响按钮边界、文字对比和输入焦点的动态模糊。

### 图像生成提示词

Logo 图形提示词：

> 为中文家庭记忆微信小程序“拾光”设计原创标志图形。两只抽象小鸟轻轻相向、彼此陪伴，象征老人和家人、两代人之间的情感连接。造型极简、轮廓概括、小尺寸清晰，带少量朦胧彩铅和点彩颗粒，玉石绿、湖水蓝、杏黄与珊瑚红的柔和渐变，大面积留白，现代东方审美。透明背景，无文字，无签名，无水印，不使用现成品牌标志，不做照片写实，不做完整场景插画。

封面／插花提示词：

> 原创现代东方国画质感插画，用抽象水面、远山、树叶或候鸟表达时间与家庭记忆。朦胧彩铅、细腻点彩、柔和渐变、轻微弥散和动态模糊感，大面积宣纸白留白，玉石绿、湖水蓝、杏黄、珊瑚红点缀，构图极简、安静而明亮，适合老年人阅读产品的封面与章节插花。不要文字、签名、水印、边框和 UI 元素，不临摹具体画作。

只用图像模型生成 Logo、封面和插花资产；界面本身必须由 WXML/WXSS 实现，不能把一张 AI UI 图当成可点击页面。

## 老人可用性和小程序约束

- 常用正文不得依赖过小字号；老人确认原文和关键按钮应明显大于装饰信息。
- 高频触控目标建议不小于约 `88rpx`，按钮之间留出防误触间距。
- 底部固定输入区和导航必须处理 `env(safe-area-inset-bottom)`。
- 检查键盘弹起、`textarea` 自动增高、输入焦点与消息滚动，不让发送区被遮挡。
- 不依赖 hover；使用 pressed、loading、disabled、Toast 或页面内状态反馈。
- 不依赖在线字体；使用可靠的中文系统字体栈。
- 艺术图片放入运行包前必须压缩，检查主包体积；不要把原型截图或带水印参考图作为运行资源。
- 保留微信胶囊区域，避免自定义元素与右上角固定按钮重叠。
- 至少检查一个较小屏幕和一个主流全面屏，并进行一次真机预览。

## 必须覆盖的状态

- 首页：空书、有片段、有章节、家人身份、老人身份、待确认数量变化。
- 采访：首次问题、正常追问、输入为空、长文字、私密选择、家庭可见选择、保存失败、离开未保存。
- 确认：待确认、全部处理完成、确认、拒绝、冲突、私密内容。
- 记忆之家：没有公开片段、确认后新增、不同成员筛选、长姓名与长关系称谓。
- 章节：无合格来源、生成中、来源变化丢弃旧结果、本地演示整理、云 AI 草稿、来源展开。
- 通用：按钮 loading／disabled／pressed、键盘、安全区、网络失败、图片加载失败。

## 建议实施顺序

1. 先建立新的视觉变量和原生小程序页面框架，不生成大量图片。
2. 先完成“人生之书首页”和“回忆采访”两个关键屏幕，在微信开发者工具中截图给用户确认。
3. 用户确认视觉方向后，完成记忆之家、老人确认和章节阅读。
4. 同步修正“未经确认不向其他家人公开”的领域逻辑并补测试。
5. 最后生成原创 Logo、封面和少量插花，压缩后接入页面。
6. 完整走通：家人进入书 → 回答共享问题 → 独立采访 → 选择范围 → 老人确认 → 时间线出现 → 生成章节 → 查看来源。
