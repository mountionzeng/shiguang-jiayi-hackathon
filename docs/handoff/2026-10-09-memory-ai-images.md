## 功能边界

- 支持本人的已确认独立记忆；家人投稿沿用既有主人权限，不在投稿页开放生成。
- 回忆配图是附图，不新增故事纸面底图；图片不会自动插入已关联故事的正文。
- “从记忆移除”只解除引用，保留原图；本轮不提供记忆生成图的永久删除入口。
- 选用前必须通过图片审核；服务不可用、额度耗尽或检查失败均不绕过。真实模型自然度、构图与手机表现尚未验证。

## 补充：生成以用户原文和照片为依据

本次反馈落实于本节所在后续提交，基于 af6ef92。

- 故事/回忆配图在有用户照片时默认参考前3张，用户明确关闭后刷新仍保留其选择。仍沿用照片 AI 授权，默认选中不等于未经同意发送。
- 已保存记忆“生成成文预览”以当前原稿与用户补充为主；有用户照片时，复用看图起草服务，先让用户核对画面描述。确认后作为独立补充字段交给成文模型；选“只用原文”就不加入照片描述。
- 同一页面、同一记忆和照片组合复用已核对的描述，避免反复付费看同一张图。照片组合变化会重新核对。AI生成的插图不会再次作为真实经历的证据。
- 看图提示只描述可见场景、颜色、物件和光线，不猜时间、地点、季节、人物关系或心理。成文时原文和用户明确纠正优先；照片中的文字不是指令，照片内容不是某次往事发生的证明。
- 云端检查照片仍属于该记忆，生成后再次核对来源。新增 photoReferenceApplied 回执，旧云函数忽略照片字段时不把输出视为照片参考成功。
- 图片不可读/识别失败不会假装已经参考；说明未参考照片，提供“只用原文”或“稍后再试”，保留草稿。用户选择不用照片可继续原文成文。原有仅照片导入的“看图写一句”入口保持；记忆成文页面仍要求有原稿文字。
- 静态检查：TypeScript、两个改动云函数语法及 git diff --check 通过。未新增/运行测试，未调用模型、部署或生成二维码。
- 待部署函数新增 organizeMemory；连同上一节 storyImages、storyBooks 一起核对版本。待真实验收：默认参考与关闭保持、照片授权拒绝、描述确认/只用原文、原文冲突、照片增删引发失效、旧云端拒绝误报、成文预览与正常保存重开。
