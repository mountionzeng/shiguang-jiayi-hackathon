# 章节正文自动保存与草稿恢复

## 问题与范围

用户反馈编辑故事里的章节正文后退出，重新打开丢失大段文字。此前 onEditorInput 只更新页面内存，editManuscript 只设脏标记和退出警告；onUnload 没有持久化，返回目录要求用户先手动保存。

本次只改故事书编辑（正文、章名、书名），不包含采访回答和记忆库编辑。保留图片任务 b22c7d2 的去重界面。未改云函数、鉴权、AI 调用或费用逻辑。

## 行为

- 每次输入同步保存本机草稿，按已验证的微信 openid、primaryFamilyId、故事 ID 隔离；本地演示使用单独 local 范围。
- 点目录、返回、切章节时先保存，保存失败留在编辑页。onHide/onUnload 先同步备份，再尽力保存；不依赖卸载回调等待网络。
- 重新加载先读远端并验证身份，再恢复尚未确认保存的本机草稿。完全离线且无法验证身份/加载故事时不展示跨账号缓存，草稿仍保留，联网后重新打开恢复。
- 保留原有 expectedRevisionId/expectedStoryVersion 乐观锁；遇到新版不会自动覆盖。提示先复制当前正文，再核对新版；“更多”提供复制正文入口。
- 原生编辑器继续管理文字和光标，输入时不回写正文到 setData，不在保存回执后重新灌入编辑器。
- 保存期间到达的新输入保留，迟到的 getContents 回调不会覆盖新输入；不确定的写入使用原 revision ID 重试。只有对应快照确认保存才清除备份，主动放弃需用户确认。
- 存储失败显式提示不能退出；云端保存失败明确说明本机备份是否成功。未支持的粘贴图片不会提交旧正文，其可读文字保留在草稿。
