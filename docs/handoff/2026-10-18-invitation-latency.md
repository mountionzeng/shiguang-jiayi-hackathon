# 邀请准备延迟（2026-10-18）

## 做了什么（附提交号）

- 延续分支 `codex/integrate-invite-20261016`，基线 `7de584a`。本轮源码提交待记录。
- 用户反馈邀请也很慢。按 ce-debug 先定位、增加固定耗时指标、实测，再改请求调度。优化前同一本书同一章的真实 `invite.prepare` 为 18591 ms；其中权限查询 1291 ms、素材审核/读取 3745 ms、创建邀请 2388 ms。
- 原准备流程为第一次快照核对（身份→当前状态→身份）、权限、素材、第二次快照核对、创建，共约 9 次串行云请求。将第一次快照核对、权限、素材三个独立读取同时运行；三项全部成功后仍进行第二次快照核对，然后创建邀请。不减少校验次数，不使用过期权限缓存。
- 素材接口自身执行服务端身份/主人/来源版本验证、内容安全检查及签名前后比对，因此不依赖客户端第一次快照核对完成。并行结果只保存在局部变量，末次核对前不会开放发送。
- 使用 allSettled 等待三项收尾再解锁重试，避免一次失败后，尚未结束的旧校验清空下一次尝试的数据。离页或快照失效不继续创建；创建结果不确定时仍提示到管理页核对，不自动重试。
- 新指标 `invite.prepare`、`invite.capabilities`、`invite.create` 只记录固定操作、路由、成功/失败及毫秒数，不含称呼、邀请令牌、账号或正文。
- 新增 3 项测试，覆盖并发启动、创建等待三项及末次核对、失败等待收尾与重复点击、首末次核对失败、校验中离页。先在旧调度上观察到 2 项失败，再修复；既有断言未放宽。类型检查与 1309 项全量测试通过，零失败/跳过。

## 和本交接不一样的地方

- 上一轮解决分享页下载全部历史的问题；本轮解决图文预览完成后准备邀请的串行等待。计时从“确认预览，准备邀请”点击处理开始，到准备结果返回，不含前面的图片生成，也不包含朋友接收。
- 最终真实流程：书架→书稿→发送给家人→同一短章节→图文预览→输入测试称呼→准备邀请成功→回书稿→管理页撤销并回读已撤销。最终 invite.prepare 为 13888 ms，对比基线 18591 ms 少 4703 ms（约 25%）。每版只有一次成功计时，不代表 p50/p95 或真机上限。首次只并行两支的中间版本为 16545 ms；不能把网络波动归因全算成代码收益。最终素材调用 6770 ms、末次核对约 4356 ms、创建 2510 ms，仍远超 2 秒。
- 最终版本预览绘制曾失败一次：book.export-render 为 error/13364 ms，界面显示“图片生成失败，请重试”；原因未能从返回错误中确定，不能断言是网络。通过页面“生成预览”重试成功后完成上述流程；此项偶发失败仍需另行排查。
- 本轮共创建 3 份名称带“验收/未发送”的测试邀请，逐份撤销并核对；均未发给任何人，原有另一份待加入邀请未动。
- 正常成功路径仍为约 9 次云请求，等候链缩短；权限关闭或初次快照失败时，素材校验可能已经启动。所有结果仅在局部变量中等待，任一校验失败不显示可发送卡片、不创建邀请。
