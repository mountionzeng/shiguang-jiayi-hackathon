# 前端与后端对接建议

本文档给前端同学使用。当前原则是：前端继续以 `main` 分支的产品和 UI 为准，后端在 `dev_backend` 分支补云端数据、来源追踪、审核、AI 生成等能力。除非双方确认，后端分支不直接改页面交互和视觉结构。

当前演示界面里哪些内容需要替换成真实用户、真实家庭、云端数据和 AI 结果，见 `docs/handoff/demo-personalization-audit.md`。

## 当前结论

- 最新 `main` 已经合入 `dev_backend`，后端会尊重新 UI 的信息架构。
- 现在页面仍以演示家庭为入口，还没有真正的“创建我的家庭”“加入家庭”“邀请家人”流程。
- 当前页面主要还是从本地演示状态读写数据；后端分支已经准备了微信云数据库和 API 适配层，但前端页面接入需要按节奏切换。
- MVP 阶段建议先跑通一个共享家庭空间，再做多家庭、多身份、多模态和复杂权限。

## 前端暂时不用改的部分

- 不需要为了后端重做页面。
- 不需要马上把所有字段展示出来。
- 不需要在小程序端保存任何 AI API key。
- 不需要在第一版实现完整账户系统；微信 openid 和家庭成员绑定可以先由云函数或后端接管。

## 前端需要预留的产品入口

### 家庭入口

后续首页建议支持三种入口：

- 创建家庭：填写家庭名、被记录人的姓名或称呼、自己的家庭关系。
- 加入家庭：通过邀请码、分享链接或二维码进入。
- 继续上次家庭：进入已绑定的家庭空间。

现在“进入林家的拾光房间”可以继续作为演示入口，但正式体验版里最好把它标成演示家庭，避免用户以为已经进入自己的家庭。

### 投稿来源

每一段文字、语音、图片、视频都必须能追踪来源。前端提交时至少要带：

- `authorMemberId`
- `authorName`
- `relation`
- `createdAt`
- `inputType`，例如 `text`、`audio`、`image`、`video`
- `visibility`，例如 `private`、`family`、`selected_members`
- `relatedMemberIds`，这段记忆和哪些人有关

同一段记忆可能由不同人重复讲述，后端会保留多份原始来源，再在整理阶段合并成结构化记忆。

### 审核状态

家庭公共记忆需要审核状态。前端展示和生成时请区分：

- `pending`：刚提交，等待老人或管理员确认。
- `confirmed`：已确认，可以进入家庭公共回忆和 AI 生成。
- `conflict`：有冲突，需要人工核对。
- `rejected`：不进入公共内容和 AI 生成。

未确认内容可以让投稿者自己看到，但不要默认展示给所有家庭成员。

### 两类 AI 生成内容

产品上建议明确区分两类生成结果：

- 回顾/回忆录：更精炼，适合章节、人生故事、纪念册、长线整理。
- 随手记：细节更丰富，适合近期素材、日常小片段、多模态动态。

前端调用生成时需要带 `generationType`：

- `memoir_review`
- `moment_note`

不要把这两类混成同一个“生成草稿”，否则后面数据会很难整理。

## 后端已经规划的主要数据表

- `families`：家庭空间。
- `family_members`：家庭成员、关系、角色。
- `source_records`：原始输入，文字、语音、图片、视频都先进入这里。
- `memories`：经过整理后的结构化记忆。
- `biography_drafts`：回忆录式章节草稿。
- `generated_artifacts`：AI 生成后的文字、图片、音频、视频等成品。
- `assets`：上传文件元数据，对应云存储 fileID。
- `ai_tasks`：AI 任务队列和状态。
- `invites`：后续家庭邀请、加入流程使用。

核心原则：原始素材永远保留在 `source_records`；AI 二创结果放在 `generated_artifacts`；两者不要互相覆盖。

## 建议前端后续关注的文件

- `miniprogram/pages/index/*`：创建家庭、加入家庭、继续家庭、演示家庭入口。
- `miniprogram/pages/interview/*`：文字、语音、图片、视频投稿，以及上传状态。
- `miniprogram/pages/room/*`：家庭记忆流、家庭成员、邀请入口、共享可见范围。
- `miniprogram/pages/review/*`：老人核对、冲突标记、确认进入公共记忆。
- `miniprogram/pages/book/*`：回忆录式生成内容和来源回看。
- `miniprogram/services/roomStorage.ts`：保留为本地演示数据层。
- `miniprogram/services/roomRepository.ts`：后续页面切到云端/后端时，建议统一从这里读写。

## AI 和云端注意事项

- AI API key 只能放在云函数或独立后端服务里，不能放在小程序代码里。
- 小程序端只提交任务，例如“整理这段文字”“生成第一章”“生成一张配图”。
- 云端负责读取已授权素材、调用 AI、保存结果，再把结果返回给小程序。
- 私密、未确认、已撤回、冲突和被拒绝的内容，不应该进入公共 AI 生成。
- 停止分享不等于删除原始素材；前端需要在文案和按钮上区分“撤回共享”和“删除原始记录”。

## MVP 验收清单

- 两台手机进入同一个演示家庭后，能看到同一批云端数据。
- A 提交一段文字后，云端 `source_records` 保留原文和投稿人。
- 老人确认后，云端 `memories` 的审核状态同步变为 `confirmed`。
- 只有 `confirmed` 且 `visibility === "family"` 的内容进入回忆录生成。
- 私密内容不会被其他家庭成员看到，也不会进入家庭公共生成。
- 回忆录和随手记生成结果分别保存，不能覆盖原始素材。
- 上传失败、云端失败、AI 生成失败时，页面有清楚的重试和失败状态。

## 对接节奏建议

1. 先保持 `main` UI 不变，后端把云端数据模型和接口跑稳。
2. 再把页面读写从 `roomStorage.ts` 切到 `roomRepository.ts`。
3. 然后补“创建家庭/加入家庭/邀请成员”的最小入口。
4. 最后接多模态上传、AI 任务队列和正式权限规则。
