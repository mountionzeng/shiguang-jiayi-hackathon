# 2026-11-04 记忆长期保留与多文章复用

## 用户要求与本次实现

原记忆独立存在，可以反复加入不同文章，也可以与其他记忆组合成新文章。继续沿用现有“加入记忆”、记忆组合和“放进书”入口，没有新增按钮或表单。

基线：ae291ac，分支 codex/document07-miniapp-acceptance-20261103。

- 复用既有 `ManuscriptChapter.memoryIds`、书籍 `memoryIds`、`addMemoryToChapter` 和 `removeMemoryFromChapter`。删除没有业务调用的旧独占 `assignMemory` 接口，统一新章节、原文入文和整理成文为追加引用，不再从其他文章移走来源。
- “移出”只移除当前章节的来源关联，保留正文、独立记忆和其他章节引用。组合面板现有来源说明显示同一记忆的多个使用位置。
- 文章的既有记忆选择器记录来源 ID；与聊天/草稿本机备份一起恢复。生成成功时固定该草稿对应的来源；生成失败保留此前草稿及其来源。点击现有入文动作后才写入文章。
- `ArticleSaveRequest.sourceMemoryIds?: string[]` 是客户端保存接口的来源快照；序列化为既有 `articleSave` 的可选 `chapter.memoryIds`。旧备份请求没有这个字段，重试时保留旧 JSON 载荷及字段顺序，避免幂等哈希变化。
- `storyBooks/article.js` 在保存正文的同一事务中追加章节和书籍来源关联。使用 `memoryExports` 的已有读取/账号档案解析方法；新增来源必须属于当前账号的个人记忆，不可删除、跨账号或绕过接收材料的权限标记。只写文章版本和书籍关系，不更新或复制记忆记录。
- 老客户端不传来源字段仍可保存，云端保留已有来源；已被删除的历史来源不阻止文章后续编辑，但不能新引用到另一篇文章。历史关联未做猜测性回填。
