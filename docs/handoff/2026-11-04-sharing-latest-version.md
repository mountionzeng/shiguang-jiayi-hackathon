# 分享使用最新已确认版本（2026-11-04）

业务提交：2a08a4fa96fcc6468abc54c1c6aac1bacd1e188a。继续用户已授权的 document07-miniapp-acceptance 候选。仅客户端修改，未部署云函数、上传正式版本、提审或发布。

## 根因

1. 新文章编辑器用 articlePending/articleSaving/flushArticle，旧分享入口的 finishEditing 只等待旧编辑器。新输入尚未得到云回执时可携带旧 savedRevisionId 进入分享；保存失败也可能继续分享旧稿。
2. 目录仍保留上次打开的 article，发送按钮仅按 article 是否存在判断，误走章节投递入口。
3. 章节发送失败后，outbox 仅按章节 ID 和接收对象复用包。即使用户已修改标题和全文，再次发送仍重放旧包；旧测试甚至要求修改正文后继续发送原包。
4. 切到其他章节后，仍保留在本机的未同步草稿没有被整书分享检查，目录显示的本机新标题可能与分享的旧云稿不一致。

云端已有不可变书稿修订、currentRevisionId/version 乐观锁和幂等回执；本次问题是编辑到分享入口的衔接以及客户端发送包复用，不能把“有历史表”当作端到端版本管理已生效。

## 修复

- finishEditing 等待新文章全部连续输入保存完毕；失败或冲突保留原草稿、明确提示，禁止静默使用旧稿。
- 整书/公开故事卡核对每个章节本机草稿，未同步时指出章节；不自动覆盖云端或丢弃草稿。
- 目录发送按 view 路由；章节投递在保存及选择完成后重新取得章节，迟到回执/切章/离页不会打开旧分享。
- outbox 增加账号范围、书籍 ID、书名和完整章节内容的来源键。相同内容的网络重试仍使用同一包和 requestId；内容变化创建新包。旧未确认请求保留，不会自动冒充新稿重发。
- 没有新增按钮，也没有改动布局、云权限、既有版本格式。
