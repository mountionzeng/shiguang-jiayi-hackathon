# 2026-11-04 按用户意图成文

用户要求：先理解材料前因后果和已有问答；知道用户在意什么、要什么效果后直接写，不重复采访。方向真正缺失才补问一个关键问题。写法选项是主动调整入口。

实现：整理成文章直接调用 organizeMemory 的 articleGuidance 模式，传入完整已保存对话（最多200条/120000字符）与云端校验的材料；本次明确写法作为 writingInstruction。独立的 articleWritingGuide.js 定义理解、选结构、成文、事实及目的复核规则。模型输出文章或一个 clarification；后者只作为聊天问题，不落成稿。用户回复该问题后直接继续成文，服务器拒绝第二轮补问。已有成稿在失败时保持，原话加入版本历史；选写法取消不修改已有内容。写作方向以会话 request 保存，重开可以调整。

边界：当前记忆正文仍限500字符，不等于长篇文章或整本书。来源归属、内容审核、模型费用和已有权限保持；不新增外部服务。
