# 撤回本机存储切换，恢复原有云端档案

## 原因与范围

用户反馈“自己创建的人物没了”，明确要求返回原来的版本。上一构建将 CLOUD_DATABASE_ENABLED 从 true 改为 false，普通页面转而读取独立的本机档案，没有延续已有云端人物与故事。测试复现了同样现象；没有通过用户微信身份直接核验真实云端记录，不能声称人物已全部恢复。

- 恢复原有 AppID、云环境、微信身份与 familyId 规则下的云端读取/保存，不更换数据库或身份。
- 不删除、覆盖或自动迁移任何真实云端/本机记录。上一构建本机数据仍留在原 storage；当前界面不自动混入本机记录。
- 移除书稿/我的页面的本机导入入口，修正存储、AI 授权和清空操作的说明，避免误认为清空只影响本机。
- 保留此前的保存重试、错误提示、历史版本、档案与亲友分工、横向工具栏和原生图文编辑修复。
- 图片文件仍只保存在手机；保存书稿时文字与不透明照片引用进入云端，照片字节不上传。跨手机无法读取原手机照片。
- 未提交、合并、push、发布或提交审核；开发预览不是线上版本。

## 验证

- 新回归测试在修复前失败，恢复开关后通过：正常仓储加载必须看到原有云端人物，不覆盖本机独立记录；云读取报错不得伪装成空本机空间。
- 恢复云端版本测试：旧稿保留、写入回执丢失重试幂等、过期编辑冲突、历史恢复和云初始化失败不落入本机。
- TypeScript 类型检查、122 项自动化测试、book/me 的官方 WXML/WXSS 编译、git diff --check 通过。测试全部使用合成数据，没有操作真实故事。
- 真实人物完整性与真机图文操作仍需用户用原微信账号验收。
- 最终代码的官方 CLI 开发预览生成成功，包大小 1,472,141 字节。二维码位于工作区父目录 `shiguang-cloud-restored-preview-20260911.png`；本次预览未发布上线。最后授权按钮文案调整后，类型检查和 11 项存储/AI 回归再次通过。

## 手机确认

用本次云端恢复构建的预览码重新进入，不要用上一版“本机图文”码。先看切换档案中的原有档案，再看亲友人物管理；若仍缺少，记录所在页面与提示，停止新增/清空，继续只读排查账号与云权限。不要删除小程序数据、清空档案或反复导入来尝试恢复。

本次优先恢复原有数据可见性；本地隐私方案以后必须在备份、迁移、恢复与连续性验证完成后另行确认，不能直接翻转全局存储开关。
