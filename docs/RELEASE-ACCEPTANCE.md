## 2026-11-02 用户授权更新：内部体验与正式发布分开

用户在本对话同意继续执行“内部体验版验证先行，正式上线仍须全部验收通过”的方案。本节优先于下文把所有体验版上传都绑定全量上线验收的旧范围说明。

- 内部体验：固定候选代码，复用对应版本有效证据，验收本次修改涉及的完整用户路径及清理结果；明确保留真机、新账号、断网及未测分支，不将未完成项填 passed。只供既有授权体验成员使用，不自动增加成员或开放公开访问。
- 正式提审/发布：仍必须完成本文件全部上线验收；内部体验上传成功不等于上线通过。
- 每次记录源码提交、云环境、实际上传版本、后台选中的体验版本和未完成项。固定体验入口必须在后台核对实际指向，不能用旧二维码冒充新包。
- 冻结代码后验收；无相关业务变化时不重复调用 AI 或跑整套 UI。已知外部阻塞记录一次，停止重复尝试。
- 现有 preview:wechat 脚本仍按完整证据校验，本次未修改脚本、伪造证据或声称已支持内部体验模式。正式交付脚本与内部体验流程不可混称。

## 固定本次包

记录版本号、Git 提交、AppID、云环境、体验版/审核版、设备、基础库版本、客户端配置 hash、实际云源码下载比对结果及日期。核对体验版真正指向本次包，不能用开发工具新版替旧审核包背书。每次实际点验后保存截图或完整录屏，禁止包含密钥、登录码或私人文章。

## 每次都做

| 证据键 | 实际操作和通过条件 |
| --- | --- |
| fresh-account-home | 从未进入过的真实微信账号，冷启动→人生之书→新建文章→输入虚构文字→保存→退出重开。没有预置房间/故事也能使用。不使用开发者身份白名单。测试夹具只是额外自动检查，不能代替此项。 |
| returning-account-cold-start | 已有账号关闭后重开，原故事/图片可加载；不清除用户数据制造“首次”。 |
| primary-navigation | 逐一点击人生之书、记下此刻、记忆之家、我的及本版可见入口，能进入/返回；无空白、死按钮和无尽加载。暂未完成的入口不能伪装可用。 |
| failure-recovery | 模拟断网后恢复网络，错误有说明且重试能恢复；取消弹层后能继续操作；不把读取失败显示成空数据或替换原故事。 |
| book-read-write-restore | 文章文字/章节编辑、保存、重开、版本查看与恢复，恢复前当前版本保留。 |
| article-question | 本版 AI 入口实际问答、整理、确认入文；记录真实调用及费用，拒绝授权不阻断普通写作。 |
| image-reference-and-layout | 上传/选图/排版/重开；生成图片按有效费用授权实际验证，不只检查按钮。 |
| cover-and-spine | 封面/底图裁切及书籍边缘视觉检查，旧图片和派生版本保留。 |

涉及传播的版本还需分别记录微信甲→微信乙、微信→网页的新故事接收与已有故事更新。接收与拒绝都尊重用户选择，图片和文字完整，拒绝不修改原故事。不能以同一个账号收自己的故事冒充跨账号通过。

## 内容及提审材料

- 公开入口、示例、分享卡片与 AI 输出的内容审核正常；不跳过文字/图片审核来解决可用性问题。
- 隐私说明、AI 授权、图片权限的取消分支可正常返回；不强求无关权限。
- 审核说明写真实操作路径。微信登录产品不应要求审核员提供微信密码；平台若需要体验说明，提供实际可用步骤及当前包完整录屏。
- 测试只用虚构内容；记录原文基线，完成后通过正常恢复/软删除流程清理增量，不删除历史或覆盖他人新改动。
- 任一项失败或未验收：**不上传为可验收版本、不提审、不发布**；写清阻塞和下一步。修复后重新验证受影响完整流程。

## 证据写法

每项保留：操作时间、包版本/提交、真实账号类别（不记 OPENID）、设备、操作步骤、观察结果、截图/录屏路径、测试内容清理结果。自动脚本仅检查证据齐全，不会替代真实操作，也不允许机械补 passed。
