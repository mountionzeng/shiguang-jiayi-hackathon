## 三、合规结论（附依据与不确定项）

1. **小程序类目**：AI 生成图片属于"深度合成"，需申请【深度合成-AI绘画】类目，交技术方算法备案截图 + 双方合作协议。个人主体不开放；**个体工商户可以申请**。
   *依据：微信开放社区多篇指引文章；不是微信官方条款原文，提交类目时以后台实际要求为准。*
2. **生成内容标识**：《人工智能生成合成内容标识办法》2025-09-01 起施行——图片要加用户能看见的显式标识；文件元数据要加隐式标识；**提供下载、复制、导出时，文件里必须保留显式标识**。
   *混元默认加显式标识；是否写入元数据隐式标识，官方文档未写，接入时实测。*
3. **图片内容安全**：`security.mediaCheckAsync` 支持云调用，异步，30 分钟内推送 `wxa_media_check` 事件；需要在"云开发控制台 → 设置 → 其他设置 → 消息推送"把该事件配到一个云函数；`openid` 必填且该用户需在近两小时访问过小程序；单文件 ≤10M。
   *官方文档没写"AI 生成图必须检测"。但故事会给家人看，按"用户可见内容"处理，接入。*
4. **人脸与长相**：《个人信息保护法》第 28 条把生物识别列为敏感个人信息，网信办 2026 年 1 月《个人信息保护政策法规问答》第 2 问明确人脸属于此类；第 29 条要单独同意；第 30 条要告知必要性和对个人权益的影响；第 23 条向其他处理者（腾讯云）提供要告知接收方并单独同意；第 55、56 条要事前做个人信息保护影响评估，报告和记录保存至少三年。
   *"用文字描述的长相"是否算生物识别信息，没查到明确说法，一律按敏感个人信息处理。设计见 7.3。*

## 四、云函数拆分

> **阶段 1 实现调整（2026-09-13）**：下表的四个职责合并成**一个云函数 `storyImages`**，按 `action` 分派（`submit` / `status` / `list` / `remove`），同一个函数挂定时触发器（每 5 分钟）并接收 `wxa_media_check` 推送。原因：微信每个云函数目录单独部署，拆成四个要把签名、出图、数据库代码复制四份；仓库里 `familyInvite` 也是一个函数多个动作。
> 超时**不能写在 `config.json` 里**（官方文档只列了 `triggers` 与 `permissions`），部署后在云开发控制台把 `storyImages` 超时设为 30 秒。
> 混元接口域名按产品名取 `aiart.tencentcloudapi.com`（公共参数页未逐字写出），版本 `2022-12-29`，地域默认 `ap-guangzhou`（官方支持广州、上海）；首次真实调用时核实。
> 签名自己实现 TC3-HMAC-SHA256，不引入腾讯云 SDK；测试用腾讯云官方示例核对规范请求与待签字符串。

仓库现有云函数都没有 `config.json`（默认超时 3 秒），新函数全部带 `config.json`。

| 云函数 | 做什么 | 超时 |
|---|---|---|
| `imageSubmit` | 校验身份和家庭成员关系 → 检查限额 → 由章节文字生成提示词 → **先写任务记录（status=submitted）再调服务商** → 保存服务商任务号 | 20s |
| `imageStatus` | 查任务；进行中就问服务商；完成就下载结果图 → `cloud.uploadFile` 写进云存储 → 写图片记录 → 提交内容安全检测。**幂等**：已转存的直接返回。另挂**定时触发器每 5 分钟**扫一遍"已完成未转存"的任务，用户关掉小程序也不会让已付费的图在 1 小时后过期 | 20s |
| `imageModeration` | 接收 `wxa_media_check` 推送，按 `trace_id` 找到图片，标记通过 / 有风险；有风险的隐藏并删云存储文件 | 10s |
| `imageManage` | 列出、删除、设为封面、设为本章底图、恢复旧图；删除文件必须在服务端做，才能校验权限 | 10s |

服务商层：`imageSubmit` 与 `imageStatus` 共用同一份 providers 代码，统一成两个方法：

```
submit({ prompt, references, width, height }) -> { providerJobId }
query(providerJobId) -> { state: "running" | "done" | "failed" | "blocked", imageUrl?, errorCode?, revisedPrompt? }
```

阶段 1 只实现 `hunyuan`；接口留好，以后要加别家只加一个文件。混元密钥建议用**只授权混元生图的 CAM 子账号**，不要用主账号密钥。

## 五、数据结构

**图片不放进书稿版本里**，单独存两个集合。理由：版本保持小；恢复旧版本不会误删图；图片的生死不跟文字版本绑在一起。

### `image_jobs`（生成记录，留痕）

```
{ _id, familyId, requesterOpenId, requesterMemberId,
  memberId,               // 当前书稿所属档案（问题四的 Story 记录出来前，章节归档案）
  storyId?,               // 问题四的 Story 记录有稳定 id 后补上
  chapterId?, purpose: "illustration" | "cover" | "backdrop",
  provider, model,
  prompt,                 // 实际发给服务商的最终提示词
  revisedPrompt?,         // 服务商改写后的（混元关闭改写时等于原文）
  source: { chapterId, textHash, textLength },
  referencePhotoCount,    // 只记张数，不存照片、不存照片哈希
  photoConsentAt?,        // 用了照片时，用户点"同意"的时间
  status: "submitted" | "running" | "stored" | "failed" | "blocked" | "unknown" | "expired",
  providerJobId?, errorCode?, errorMessage?,
  imageId?, createdAt, updatedAt }
```

删除图片时任务记录保留（去掉文件引用），用于对账和追溯。

### `story_images`（图像管理的主表）

```
{ _id: imageId, familyId, memberId, storyId?, chapterId?, purpose,
  fileID, width, height, bytes,
  moderation: "pending" | "pass" | "risky" | "review",
  aiGenerated: true, jobId, createdAt, deletedAt? }
```

### 文字那边只加可选引用

- **章节底图**：`ManuscriptChapter.backdropImageId?: string`。跟着版本走——恢复旧版本，底图选择也回到当时的。章节 id 跨版本稳定（问题四已保证）。
  *已核：`cloudRoomStorage` 保存书稿时整份 `draft` 写入，新增的章节字段会保留。但 `manuscript.ts` 的 `revisionContent` 逐个字段比较章节，只换底图时版本会被当成"没变化"——必须把 `backdropImageId` 加进去。问题四确认：`copyChapter` 用展开写法会自动带上新字段，存储层没有按字段白名单过滤章节。*
  *章节合并 / 拆分还没做。问题四打算：合并时保留前一章的 id，拆分时前半段沿用原 id、后半段用新 id（尚未问过用户）。照此规则，合并后后一章的底图选择会丢，拆分出的后半段没有底图——做这两个功能时要提示用户。*
- **故事封面**：等问题四的 Story 记录（有稳定 id，改名不变）出来后，在 Story 上加可选字段 `coverImageId`。**不挂在 `ShelfStory.key` 上**——问题四确认它是过渡字段，改名就变。在 Story 记录出来之前，不做"设为封面"的保存。
- **插图**：阶段 1 **不插进正文流**（不改 `ManuscriptContent`），挂在章节下，显示在章节正文之后。原因见"旧客户端兼容"。

## 六、提示词怎么来（不得编造）

两步：

1. **现有文字模型**（`AI_API_KEY`）读章节标题 + 正文，输出结构化 JSON：`{ scene, objects[], light, mood, eraHint? }`。系统提示词要求：只能描述正文里出现过的物件、场景、季节、光线；正文没写的人名、年份、地点、事件一律不写；`eraHint` 只在正文明确提到年代时填；人物只写"远景中的背影""手部特写"这类不露清晰面部的构图。
2. **模板拼接**最终提示词，**全部用肯定式**（不写"不要画××"），按用途加风格尾巴：
   - 插图：纸本淡彩水彩，暖白纸底，留白充足；
   - 底图：画面主体集中在下缘和边角，上方大面积接近纯纸白的留白，低对比、色彩稀薄、纹样稀少，适合在上面排文字；
   - 封面：竖幅，主体居中偏下，上方为书名签条留出干净区域。

混元的 `Revise`（提示词改写）**关闭**：它会加 20 秒，而且可能扩写出正文里没有的内容。最终提示词和服务商返回的 `revisedPrompt` 都记进 `image_jobs`，管理页可以查看"这张图是根据什么画的"。

## 七、照片：识别、特征与参考图（阶段 2b）

### 7.1 授权与传输

**腾讯云会怎么处理发过去的照片**（《腾讯云大模型服务条款》原文，适用于混元生图与混元生文；混元生图常见问题页对留存、训练、处理地点均未写）：

| 问题 | 条款原文 | 条号 |
|---|---|---|
| 会不会拿去训练 | "除另行获取您的授权同意外，腾讯云不会将您输入的内容用于开发或改进本服务的算法、模型等。" | 4.2 |
| 保存多久 | "仅在为提供本服务之目的所必需的期间内保留您的数据……在数据处理期限结束后停止一切数据使用行为，或者根据您的指示将相关数据返还给您或删除。" **没有写具体天数。** | 2.13 |
| 在哪处理 | "数据处理地点为中华人民共和国境内。" | 2.13 |
| 腾讯的身份 | 基于客户的委托、指令处理，"不能超出您的指示范围"（受托处理） | 2.12 |
| 我们的义务 | "如您的输入内容涉及个人信息，请您确保您已经取得相关个人信息主体的知情同意（涉及敏感个人信息的，应获得单独同意）" | 2.8(3) |

授权弹窗据此如实写：发给腾讯云（混元）、在中国境内处理、腾讯云不会拿去训练、腾讯云只在生成所需期间保留（条款没写具体天数）、拾光家忆自己不保存照片。**不写"立即删除""不留存"这类条款没承诺的话。**

- **默认关闭**。每次生成底图时，若用户想用照片，单独弹窗：发给谁（服务商名称）、发哪几张（显示缩略图）、做什么用、服务商日志政策仍适用；点"同意"才发。"我的"页有总开关，随时关。
- 手机上先压缩：长边 ≤768，JPEG，逐步降质量直到每张 ≤100KB，最多 3 张（混元上限）。
- 照片以 base64 随云函数调用传给 `imageSubmit`，**只在内存里转给服务商，不写数据库、不写云存储**。
  *已核：微信官方文档没写 `callFunction` 参数上限，只建议超过 100KB 的字段用 `wx.cloud.CDN` 标记改走临时 CDN，而临时 CDN 保存多久文档未写。所以不走临时 CDN，免得多一处照片落地；压不到 100KB 的那张不发并告诉用户。上线前真机实测。*
- 必须改的文案（**措辞由用户定稿**）：`services/aiConsent.ts` 里"不发送照片"；`pages/me/me.wxml` 里"照片文件仅保存在本机"；微信后台《用户隐私保护指引》增加"照片（经单独同意，用于生成章节底图）"及第三方；然后重新提审。
- `HACKATHON_COMPLIANCE.md` 的"第三方依赖"需补图像生成服务；"与既有项目的边界"一节不受影响。**措辞由用户定。**

### 7.2 识别什么（参考网页版的做法，在本仓库独立实现）

- 现有照片入口只有书稿页「照片」按钮（一次一张，存本机）；聊天页的「照片 · 赛后接入」不在本线范围。
- **不自动识别。** 书稿里点某张照片 →「让 AI 看看这张照片」→ 先选想认出什么：「场景和物件」「某个人的样子」（可多选）。不选就不上传、不识别。
- 看图模型：混元视觉理解（`hunyuan-vision` 系列，OpenAI 兼容接口，图片以 `data:image/jpeg;base64,…` 传入，默认 5 并发）。价格输入 ¥3、输出 ¥9 每百万 tokens，一张照片预计不到一分钱（**待实测**）。
  *备案：检索结果显示混元大模型为 网信算备440305295988701230071号，但官方接口页没写视觉模型对应哪个备案号，下载合同时核对。单张图片大小、一次最多几张，官方文档未写，实测确定。*
- 输出结构化 JSON，**先作为"待确认"给用户看**，每一条可改、可删，确认后才保存、才会进提示词；看不清的写"看不清"，不猜：
  - 场景：地点类型、季节、光线、主色调、材质、年代线索（只写照片里看得出的）；
  - 物件：名称 + 一句描述；
  - 人（仅选了「某个人的样子」时）：先列出照片里每个人的位置（如"左边穿深色外套的人"），用户点选**一个**并指明是家里哪位成员，只提取这一个人的发型、衣着、配饰、体态、大致年龄段、面部轮廓的文字描述。**其他人不提取。**
- 只存文字描述，不存照片、不存人脸向量或任何生物特征模板。新集合 `photo_insights`：

```
{ familyId, memberId, storyId?, chapterId, photoId,   // photoId 是本机照片的不透明引用
  kind: "scene" | "object" | "person", memberId?,
  fields, status: "draft" | "confirmed",
  consentAt, confirmedBy, confirmedAt, model }
```

### 7.3 长相特征的护栏

- **「识别长相」是单独的开关，默认关闭。** 在单独同意弹窗、《用户隐私保护指引》新增条目并**重新审核通过**之前，这个开关不对用户开放；这段时间底图和插图只用「场景和物件」（场景、色调、构图、物件），不识别人脸。（协调会话要求，2026-09-13；用户"场景和长相都要"的决定不变，只是长相晚一步开放。）
- **单独的同意弹窗**，不和普通 AI 授权合并：写明接收方（腾讯云混元）、用途（让插图里的人像 TA）、为什么需要、可能的影响、照片不保存、特征可随时删除。
- **本人给自己认长相**可以直接做；**替家人认**（比如孙辈上传爷爷的照片），要爷爷本人在自己的微信里确认后才提取，没确认前只做场景物件。
- "我的"页新增「AI 记住的长相」，本人可查看、修改、删除；删除后已生成的图不自动删，但之后不再使用。
- 人物用纸本淡彩插画风格，不做写实照片风格；人物参考**只用确认过的文字描述，不把有人脸的照片当参考图传给生图模型**（参考图只用只选了「场景和物件」的照片）。
- 只有章节正文里提到这个人时，才把他的长相描述放进提示词。
- 处理长相特征前，按个保法第 55、56 条完成个人信息保护影响评估（我起草，用户定稿并保存）。

### 7.4 生成图质检（阶段 2a 起）

出图后用同一个看图模型检查：有没有可读文字或乱码字、除"图片由AI生成"以外的水印 / logo / 签名。发现了就标"有瑕疵"，由用户决定是否换一张（换一张另算费用），不自动重画。

- 每张卡片：缩略图、用途、生成时间、状态（正在画 / 审核中 / 没画成 / 不确定）、"AI 生成"角标；
- 操作：**设为封面**、**设为本章底图**、**换一张**（重新生成同用途；旧图保留，可切回，直到删除）、**删除**（二次确认；正在当封面或底图的先解除）、**查看依据**（提示词与来源章节）；
- 页头显示占用："这个故事的图共 N 张 · X MB"。

**与 Codex 的分工**（协调会话 2026-09-13 划定）：

- 归问题五：生成、管理图片的一切——「这个故事的图」管理页、书稿每章「配图」入口、设为封面的逻辑与数据字段、底图、云函数、测试；
- 归 Codex：书壳、书名签条、书架的样式文件与图标素材；
- 交界处：封面图显示在 Codex 的书壳里时，只在数据上提供封面图，在书壳模板里用最小改动接上（加一个 `image` 节点或一个类名），不重写它的样式。**改到 Codex 的文件前，先在问题五的对话里告诉用户改了哪几行。**

## 九、失败与超时怎么表现

每种结局明确区分，**不用"数据缺失"表示失败**：

| 状态 | 什么时候 | 用户看到 | 算不算限额 |
|---|---|---|---|
| 正在画 | 已拿到任务号 | "正在画，大约 20–60 秒。可以先离开，回来接着看" | 算 |
| 到上限 | 今天已画 10 张，或这个故事已满 30 张 | "今天的 10 张画完了，明天再来" / "这个故事已经有 30 张图了，删掉的不会返还名额" | — |
| 没画成 | 服务商明确返回失败 | "没画成，没有扣费，可以再试一次" | 不算（混元失败不计费） |
| 没通过审核 | `OperationDenied.*` 或检测 risky | "这段内容没通过平台审核，换一段试试"；不自动重试 | 不算 |
| 不确定 | 提交时超时、没拿到任务号 | "不确定有没有画成，可能已经扣费"；**不自动重试** | 算 |
| 过期 | 画好了但 1 小时内没转存 | "画好了但没来得及保存"；定时触发器兜底，应极少发生 | 算 |

小程序轮询：前 90 秒每 3 秒一次，之后每 10 秒，离开页面停止。

## 十、旧客户端兼容

- 新字段全部可选，新数据在新集合，旧客户端读不到也不报错；
- 阶段 1 不改 `ManuscriptContent`：旧客户端 `validateContent` 遇到不认识的正文项会报"图文内容格式无效"，所以插图先不进正文流；
- 旧客户端看到的封面仍是原来的淡彩书壳；旧客户端保存书稿会整份写回 `draft`，会带着自己读到的 `backdropImageId` 原样写回，不会丢；
- 家庭删除 / 重置 / 巡检类云函数（`resetCurrentUserRoom`、`deleteDemoFamilyOnce`、`inspectFamilyData`）和 `ensureCloudCollections` 要加上新集合，并删掉云存储里的图片文件，否则删家庭会留下孤儿图片。
