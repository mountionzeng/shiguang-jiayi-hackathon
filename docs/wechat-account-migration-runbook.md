# 微信小程序换账号迁移手册

这份手册适用于“新建另一个微信小程序账号并迁过去”，不是同一账号只变更主体。新账号会有新的 AppID，用户的 OpenID 也会变化，不能把换号当成只改一行 AppID。

## 迁移原则

- 旧账号和新账号先并行，验证完成后再切流；不要直接覆盖旧环境。
- 密钥只进入云函数环境变量，不写入仓库、文档或迁移包。
- 新 AppID 未登记云环境时，客户端应停止云端读写，不能静默连接旧环境。
- 迁移脚本使用业务侧稳定 ID（例如家庭、成员、内容 ID），不以 OpenID 作为跨账号主键。
- 数据导出、导入、校验、回滚都要保留审计记录；原始导出包加密并限制访问。

## 账号绑定点

只有下面两个代码配置入口应直接出现账号绑定值：

1. `project.config.json` 的 `appid`。
2. `miniprogram/config/wechat-accounts.json` 的 AppID → 云环境映射。
3. `miniprogram/config/wechat-accounts.js` 是由配置命令同步生成、供小程序真机加载的脚本副本；不要单独手改。

用配置脚本减少手工漏改。默认只预览，不写文件：

```bash
npm run configure:wechat -- --appid wx0000000000000000 --env new-cloud-env
```

确认预览无误后显式增加 `--write`。脚本会更新 `project.config.json`、JSON 映射和真机脚本副本，新增映射并保留旧 AppID，便于新旧账号并行验证；它不处理或复制任何密钥。

云函数从 `cloud.getWXContext()` 读取当前 AppID/OpenID。`drinkingTimeBridge` 不再回退到旧 AppID；极少数上下文取不到 AppID 时，使用云函数环境变量 `WECHAT_APP_ID`，缺失则明确失败。

不含密钥的部署资源清单在 `deploy/wechat-cloud.manifest.json`。换号时复制资源结构，不复制密钥值。

## 切换前盘点

- 记录旧账号 AppID、云环境 ID、环境套餐、地域和腾讯云主体。
- 导出所有云函数的名称、运行时、超时、环境变量名称、触发器和 OpenAPI 权限。
- 导出集合、索引、数据库权限、云存储权限和消息路由。
- 统计每个集合的记录数、云存储对象数与总字节数，生成迁移前校验表。
- 确认隐私保护指引、服务类目、备案、算法合作协议和第三方 AI 说明能用于新主体。
- 确认旧账号是否还需要保留线上服务、多久只读、何时下线。

## 新账号重建顺序

1. 在新账号创建独立云环境，不复用旧账号的生产环境。
2. 用 `npm run configure:wechat -- --appid <新AppID> --env <新环境ID> --write` 更新账号配置；脚本会保留旧映射用于并行验证。
3. 按 `deploy/wechat-cloud.manifest.json` 创建集合和索引。
4. 部署云函数，再逐项填写新环境的密钥；共享 Token 需要在新环境重新生成，不能从日志或代码复制。
5. 重建定时触发器、`wxa_media_check` 消息路由、数据库规则和存储规则。
6. 配置新账号的隐私保护指引、服务器域名、业务域名、服务类目和审核材料。
7. 上传体验版，用新微信号从零验证注册、家庭邀请、照片上传、内容检测、AI 配图和删除流程。

## 数据和身份迁移

新 AppID 会导致同一微信用户得到不同 OpenID。若两个小程序绑定到同一个微信开放平台账号，可评估用 UnionID 协助识别；没有可靠 UnionID 时，不应自动猜测两边是同一人。

如果旧账号确认只有一个用户，可以采用更简单的一次性迁移：新账号首次登录后，由管理员核对本人身份，把新 OpenID 对应的 `user_accounts` 记录写入旧账号原有的稳定 `accountId` 和 `primaryFamilyId`。仍需先备份和对账，不允许仅凭“数据库里只有一条记录”自动认领；迁移完成后验证新账号只能看到这一位用户的数据，再关闭一次性操作入口。

建议采用一次性迁移码：旧账号中已登录用户主动生成短期迁移码，新账号登录后输入或扫码确认，服务端把“旧 OpenID 对应的业务成员”绑定到新 OpenID。迁移码必须短期有效、一次使用、服务端哈希保存，并记录确认时间。管理员不应手工抄写 OpenID。

数据导入时：

- 保留业务 ID、创建时间、作者关系和审核状态；为原账号身份另存不可逆迁移引用。
- 云存储文件复制到新环境后重写 fileID，不要假定旧 fileID 在新环境可读。
- 对记录数、抽样哈希、文件大小和引用完整性做迁移前后对账。
- 如果法律或平台要求重新取得同意，先取得同意再迁移照片和 AI 处理记录。
- 保留故事内容块 ID、不可变来源许可和公开发布/导出限制；不能因换 AppID、复制 fileID 或重新生成故事卡而把受限来源改成自有内容。迁移后的故事卡必须重新鉴权并从新环境签发短期照片地址，旧环境临时地址不得写入迁移包。

## 切流与回滚

- 切流前冻结旧环境写入，完成最后一次增量迁移和对账。
- 新账号先灰度给内部测试人员；关键链路通过后再提交审核和发布。
- 回滚不是把新 OpenID 写回旧账号，而是恢复旧账号服务并停止新环境写入。
- 在保留期结束前不要删除旧环境；删除前再次导出、校验并取得负责人确认。

## 完成标准

- 新账号体验版可以独立运行，不访问旧环境。
- 所有函数、变量、触发器、集合、索引、规则和消息路由均与清单一致。
- 新旧数据对账通过，照片引用可访问，身份迁移有用户确认记录。
- 隐私指引、第三方 AI/照片存储说明、服务类目和备案主体均与新账号一致。
- 用迁移前后同一组允许/禁止样本核对亲友转发、公开故事卡和照片导出结果一致；新 OpenID 不会获得旧主体未拥有的发布权限。
- 回滚演练成功，旧环境保留期限和最终删除责任人已记录。
