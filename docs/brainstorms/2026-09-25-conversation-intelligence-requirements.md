# 对话智能需求

## Summary

用户期待的是：小忆读懂你刚写下的那句话，然后问一个**和你这个人息息相关**的问题，
帮你挖到更深的想法。现状是：**模型从未参与过这个对话。**

从 `main` 构建的包里，`aiReady = CLOUD_AI_ENABLED && CLOUD_AI_RELEASE_READY`
（[app.ts:51](miniprogram/app.ts)）恒为 `false`，所有文字 AI 走本地兜底。
用户看到的追问来自 [interview.ts](miniprogram/domain/interview.ts) 的固定模板表：
五个方向（人物/时间/地点/经过/感受）× 每方向 3–5 句，用正则判断哪个方向还没问过，轮着问。

**真机证据**（2026-09-25 截图）：用户输入「越是迷茫的时候，越是要往远处看。」，
小忆回「那时候谁和你在一起？」—— 这句是 `PERSONAL_FOLLOW_UP_TEMPLATES.person[0]` 的原文，
标签「再聊聊」即 `FOLLOW_UP_LABEL`（走通模型时该显示「文字 AI 生成」）。
它没有读那句话，只是正则没匹配到人物词，于是轮到了「人物」这一格。

因此本需求分三层，**顺序不可颠倒**：

1. **让模型真的跑起来**，并在界面上区分模板与模型（否则无法判断任何后续改动是否生效）。
2. **让追问的方向选择**从「正则轮询五个维度」改为「由这个人的已知倾向决定」。
3. **让这个倾向可被观察、被用户纠正、被撤回。**

第 2 层是本轮真正新增的产品判断，来自用户原话：

> 如果用户他就是一个不大在乎他身边的人的人，咱们其实是可以学习的，
> 那咱们就需要问他自己的感受从而帮他挖掘他这个人，而不是一段关系。

现有实现把「人物」写成五个固定维度之一，**结构上假定了每个人的记忆都以关系为轴**。
本需求要把这个假定去掉。

已确认的产品选择（2026-09-25，用户当场决定）：
**倾向必须对用户可见、且可以改口。** 不做「AI 悄悄学、只体现在提问里」的隐式方案。
理由是可验证性：隐式方案无法判断它学对没学对，也就无法判断「命中」——
这正是前两轮交付失手的模式。

## Problem Frame

用户的期待不是「更聪明的机器人」，而是一句很具体的话：
**AI 看到我写的字，问一个跟我这个人、或我在乎的人相关的问题。**

现状有三层错位，层层叠加：

**第一层：模型没参与。** `CLOUD_AI_RELEASE_READY = false` → `aiReady = false` →
`interviewService.canUseCloudAi()` 返回 false → `localFallbackPrompt(input, "cloud-not-ready")`。
`biographyService`（第 82 行）与 `memoryOrganizerService`（第 36 行）同一道判断。
云函数侧还有第二道 `AI_SERVER_RELEASE_READY !== "true"` 抛 `AI_RELEASE_NOT_READY`，
第三道 `PERSONAL_MEMORY_ENABLED`（2026-09-23 部署记录为 `false`、未配供应商密钥）。
**这三道开关的当前线上实际值需在控制台确认，CLI 读不到。**

**第二层：本地兜底是一个表格轮询器。** 它不理解语义，只做两件事：
正则扫描答案里出现过哪些维度词（`DIMENSION_KEYWORDS`），然后从没问过的维度里挑一个，
取该维度模板数组里的下一句。截图里的失配就是这么产生的——
「越是迷茫的时候，越是要往远处看」里没有人物词，于是轮到人物，
于是问「那时候谁和你在一起？」。**用户的原话与问题之间没有任何语义联系，这是设计使然。**

**第三层（本轮新增判断）：即使模型跑起来，方向仍由五个固定维度决定。**
`INTERVIEW_DIMENSIONS = ["person","time","place","event","feeling"]` 把「人物」
写成了必经维度之一，结构上假定人人都以关系为轴。对于一个不太在意身边人的用户，
正确的做法是问他自己的感受、挖他这个人，而不是反复追问一段关系。

同时必须避免用户原文已经点出的两个反向风险：

- **审问感**：表格化采集会让人觉得在被盘问。当前实现正是纯表格轮询。
- **歪曲记忆**：过早创作会替用户编话。`chatInterview` 第 6 条与第 11 条已有相应约束
  （暂定语气、不虚构因果与他人动机、不替他回答、不给人生结论），这些规则要保留。

### 一个已经写好但从未运行的规则集

`cloudfunctions/chatInterview/index.js` 的 `FOLLOW_UP_RULES` 有 12 条，
与用户期待高度重合，但因第一层问题从未执行。摘三条对照：

| 用户 2026-09-25 的原话 | 已存在的规则 |
|---|---|
| 「为什么会喜欢这句话？会让你想到某个人吗？是什么感受？」 | 第 11 条：从他提到的具体细节，邀请他回想当时注意到什么、如何选择、现在怎么看；一次只走一步 |
| 「根据用户不同思维逻辑问不同的问题」 | 第 5 条：不按固定轮数升级；用户主动谈感受时不把他拉回事实盘问 |
| （不要替用户下结论） | 第 12 条：只能顺着用户实际说出的内容问，不能替他说「你一直被责任压着」 |

**结论：本需求的第 1、2 层不是「新增能力」，是「让已有能力真的运行、并被看见」。
只有第 3 层是真正的新设计。写文档与排期时不要把三层当成同等工作量。**

## Actors

- **A1 讲述者**：写下一句话或回答每日一问的人。他可以纠正、否定、忘掉小忆对他的任何理解。
- **A2 小忆**：读用户的话，提一个贴着这句话、且贴着这个人的问题。
  它可以有暂定理解，但必须标明来源与依据，且永远可被否定。
- **A3 家人**：提供另一个版本的叙述。本轮不改家人协作流程，
  只要求「不同说法各自保留来源、不裁决谁更可信」这条既有规则在模型路径下继续有效。

## Key Flows

**F1 读懂这一句（第 1、2 层）**
用户写下任意一句话 → 模型读它 → 回一个与这句话有语义联系的问题 →
界面标明「文字 AI 生成」。模型不可用时回退到模板，**界面必须如实显示是模板**。

**F2 按这个人的方式问（第 3 层）**
小忆读取该用户已确认的倾向（例如「更愿意从自己的感受讲起」）→
在同样贴着原话的前提下，选择与该倾向一致的切入角度 →
倾向不明时不猜，走通用的「贴着原话追问」。

**F3 看见并改口（第 3 层）**
「小忆记住的事」页面列出每条理解、来源标签与依据 →
用户可以「说得对」「不对」「忘掉」→ 纠正后倾向立即改变，
被忘掉的理解不再从相同证据重新提炼。

## Requirements

### 第一层：让模型真的运行，并让用户分得清

- **R1** 在线 AI 走通时，追问必须来自模型；模型不可用时回退模板。
  两者在界面上**必须可区分**：现在模板显示「再聊聊」、模型显示「文字 AI 生成」，
  但用户无从知道「再聊聊」意味着 AI 没参与。至少让降级可感知（不必解释技术原因）。
- **R2** 三道发布开关的启用顺序与责任人写清：客户端 `CLOUD_AI_RELEASE_READY`、
  云函数 `AI_SERVER_RELEASE_READY`、个人记忆 `PERSONAL_MEMORY_ENABLED`。
  **不得把 `CLOUD_AI_RELEASE_READY = true` 提交进仓库**（仓库既有做法：只在隔离预览副本开启）。
- **R3** 开闸后必须用真机复测截图里的同一句话
  （「越是迷茫的时候，越是要往远处看。」），确认追问与这句话有语义联系。
  **这是本需求最小的成功证据，任何后续改动都以它为基线。**

### 第二层：问题必须贴着用户刚写的那句话

- **R4** 追问必须与用户最新一句话有可指出的语义联系。禁止出现「与原话无关的维度轮询」。
  判据：能从原话里指出这个问题所回应的那个词或那个意思。
- **R5** 对**箴言、感想、评价**这类没有人物／时间／地点的输入，
  不得追问事实要素。应追问它对这个人的意义：为什么记下它、什么时候第一次觉得它对、
  它和自己的什么经历有关。（截图里的失配正属于此类。）
- **R6** 保留 `FOLLOW_UP_RULES` 现有的 12 条约束，特别是：不虚构事件／因果／他人动机，
  不替用户回答，不用「是不是因为……」暗示答案，不给人生结论，
  不把普通回答解读成成长或疗愈。**这些是本产品可信度的地基，不得为了「更有洞察」而放宽。**
- **R7** 每日一问的回答是对话起点，不是问卷终点（第 12 条已有，需在模型路径下验证）。

### 第三层：按这个人的方式问，并让他能改口

- **R8** 提问的**切入角度**由该用户已知倾向决定，而不是固定五维轮询。
  至少支持三种倾向：偏关系（问身边的人）、偏自我感受（问他自己）、偏事物与场景（问物件与地点）。
  倾向只影响**问什么角度**，不改变 R4「必须贴着原话」。
- **R9** 倾向必须来自**可追溯的证据**：哪几次讲述、什么时间。
  不得由单次对话下结论，不得因用户讲得详细或重复多次就提高可信度
  （第 2 条既有约束）。
- **R10** 倾向对用户**可见**，并带来源标签与依据。现有页面已区分
  「小忆的暂定理解」「依据你的纠正」「依据你的讲述」，沿用这套措辞。
- **R11** 用户可以**否定**一条理解（「不对」），否定后倾向立即改变，
  并记为 `user_corrected`。**这是本轮需要新增的入口** ——
  现有页面只有「忘记」，没有「说得对／不对」。
- **R12** 用户可以**忘掉**一条理解，此后不再从相同证据重新提炼
  （tombstone 抑制已实现，保持不变）。
- **R13** 倾向不明或证据不足时，**不猜**。走通用的贴着原话追问，
  不显示任何暂定理解。**宁可少一条洞察，不要一条错的。**

### 隐私与归属（沿用既有，不放宽）

- **R14** 个人感受属于讲述者，不需家人批准；他人的意图仍待确认。
  不得声称已联系家人、核对事实或读取未提供的私密记录（第 7 条既有约束）。
- **R15** 每次在对话中使用一条理解前，重校其证据源文指纹；
  不一致则不使用（`PERSONAL_MEMORY_SOURCE_CHANGED` 已实现）。
- **R16** 个人记忆需用户独立开启，与文字 AI 授权分开。跨账号隔离与
  「忘记后不复活」必须双账号验收（既有约束）。

## Acceptance Examples

**AE1（基线，必须先过）** 输入截图里的原话「越是迷茫的时候，越是要往远处看。」
→ 追问与这句话有可指出的语义联系，例如「这句话你是什么时候第一次觉得它对的？」
→ 界面显示这是模型生成。
**不通过的样子**：出现「那时候谁和你在一起？」这类与原话无关的维度轮询。

**AE2** 同一句话，在「偏自我感受」倾向下 → 问他自己（为什么记下它、此刻的感受）；
在「偏关系」倾向下 → 可以问它是否让他想到某个人。
**两种情况都必须贴着原话**，不得变成「按标签套问题」。

**AE3** 用户说「没新事情，就想聊聊这种踏实的感觉」→ 顺着感受继续，
不把他拉回事实盘问，不收尾告别（第 5、10 条既有规则，需在模型路径下验证）。

**AE4** 一个从不提及身边人的用户，连续三次讲述后 → 「小忆记住的事」出现
「我注意到你更愿意聊自己的感受，而不是身边的人」，附三次讲述的日期作为依据。
**不通过的样子**：只凭一次对话就下这个结论。

**AE5** 用户点「不对」→ 该理解记为 `user_corrected`，倾向随即改变，
下一次提问不再按旧倾向选角度。

**AE6** 用户点「忘掉」→ 理解消失，相同证据不再重新提炼，原话与故事均不受影响。

**AE7** 倾向证据不足时 → 页面不显示任何暂定理解，对话走通用贴原话追问。
**不通过的样子**：为了展示能力而给出一条低置信度的猜测。

**AE8** 另一个微信账号无法读取或影响该用户的任何理解（双账号真机）。

**AE9** 模型不可用时 → 回退模板且界面可感知，不冒充 AI。

## Success Criteria

以下四条中**前两条是硬门禁**，没过就不算这轮做完。

1. **语义相关率**：取 20 条真实风格的输入（含至少 5 条箴言／感想类），
   人工判断追问是否能从原话里指出它回应的那个词或意思。
   **改前基线需实测**（预期接近 0，因为模板不读语义），**目标 ≥ 90%**。
2. **箴言类不问事实要素**：那 5 条箴言／感想输入，**0 条**被追问时间／地点／人物要素。
3. **倾向准确性**：对至少 3 个不同风格的测试账号，小忆给出的倾向与人工判断一致，
   且每条都有可追溯证据；出现错误倾向时，用户点「不对」后能立即改变。
4. **用户愿意从记录走向发现**（用户原文第 7 条要的验证）：
   观察「小忆记住的事」页面的打开率与「说得对／不对」的点击率。
   **如果没人打开这个页面，第 3 层的可见性价值不成立** —— 这是需要诚实面对的假设。

### 明确不作为成功标准的东西

- **测试通过数**。前两轮交付都出现过「测试全绿、产品没变」：
  美术那轮六层全加上、931 项测试通过，实测提示词 67.2% 逐字不变、情绪层命中率 8%。
- **有没有实现某个功能**。R8 可以被实现成「按标签套问题」，每条需求都满足而体验更差。
  **判据必须是上面那四条可观测指标，不是功能清单。**
- **单次成功的漂亮样例**。至少 20 条输入、含箴言类，才能排除挑样本。

## Scope Boundaries

### 本轮不做

- **不改家人协作与投稿审核流程。** 只要求既有的「各自保留来源、不裁决谁更可信」
  在模型路径下继续有效。
- **不建信息网络的可视化。** 用户原文第 4 条已经自己划了界：「不要为了图谱而做图谱」。
  本轮的「网络」只是倾向背后那几条证据链，用户看到的是几句话，不是一张图。
- **不与网页版共享倾向。** 两端的对话是两件事：小程序是记忆采集，
  网页版 `storyConversation.ts` 喂给模型的是 `storyCards` 与 `shots`
  （subject／action／shotType／cameraAngle／timeLight），那是把故事变成镜头。
  账号连续性已有 `shiguangStoryAccess` 与 `drinkingTimeAccount` 桥，够用。
- **不放宽任何禁造边界**，不为了显得有洞察而允许推测因果、他人动机或心理诊断。
- **不改限额与计费口径**（`textComputeUsage` 既有）。
- **不改指纹算法**（`sourceFingerprint`）——改了会让已存书稿被判过期而隐藏正文。

### 明显不属于这个产品

- 给用户贴可见标签（「你是感受型」）。呈现的必须是可否定的暂定理解。
- 心理测评、人格分类、情绪打分。
- 替用户总结人生结论或安排任务（第 8 条既有约束）。
- 主动替用户联系家人核对事实（第 7 条既有约束）。

### 留给后续

- 从倾向走向「主动发现缺口」：告诉用户「你三次提到那口灶台，但从没说它后来去哪了」。
  **这需要第 3 层先跑准**，否则会变成基于错误理解的骚扰。
- 跨故事的主题发现与家族叙事组织（用户原文的后半段目标）。
- 家人之间的分歧呈现界面（保留分歧已有数据基础，呈现方式另议）。

## Key Decisions

| 决定 | 理由与边界 |
|---|---|
| 倾向对用户可见、可改口 | 用户 2026-09-25 当场决定。隐式方案无法验证学得对不对，也就无法判断命中 |
| 三层顺序不可颠倒 | 第 1 层不通，后两层的任何改动都无法观察，等于盲改 |
| 第 1、2 层是「让已有的跑起来」，不是新增 | `FOLLOW_UP_RULES` 12 条已写好且与用户期待重合，只是从未执行 |
| 只有第 3 层是新设计 | 「倾向」需要跨会话积累与用户纠正，提示词做不到 |
| 倾向只影响提问角度，不影响「必须贴着原话」 | 否则会退化成按标签套问题，重新产生审问感 |
| 不给用户打可见标签 | 呈现的是「我注意到你更愿意聊自己的感受」这类可否定的暂定理解，不是「你是感受型用户」 |
| 复用 `personal_memory_*` 现有结构 | `origin`／`confidence`／`evidenceIds`／tombstone／指纹重校都已实现并验收过 |
| 沿用现有页面 | 「小忆记住的事」已存在并已区分三种来源标签，本轮补纠正入口即可 |
| 保留全部 12 条对话约束 | 可信度地基。「更有洞察」不能以放宽禁造边界为代价 |
| 不改家人协作流程 | 本轮只要求「各自保留来源、不裁决谁更可信」在模型路径下继续有效 |

  单次对话延迟已实测 4.7–16.7 秒，整理阶段最慢。
  **假设**：追问属于短输出，延迟接近 4–7 秒区间；需实测确认是否影响对话体感。
- **依赖**：三道发布开关的线上实际值。**CLI 读不到云函数环境变量，必须控制台确认。**
- **依赖**：个人记忆供应商密钥。2026-09-23 记录为「尚未配置，不能启用提取」。

## Outstanding Questions

### 需要用户在实施前决定

- **倾向在哪里呈现？** 只在「小忆记住的事」页面（用户要主动去看），
  还是在对话中适时出现一次（更容易被看见，但可能打断讲述）？
- **纠正后要不要立刻体现？** 用户点「不对」之后，下一个问题就换角度，
  还是等下一次对话？前者反馈更强，但可能显得突兀。

### 留给规划阶段

- 倾向的判定阈值（几次证据、多长时间窗口才足以形成一条倾向）。
- 三种倾向之外是否需要更细的分类 —— **建议先只做三种，做准再扩**。
- 网页版「聊聊」是否共享同一份倾向。**本轮不做**，见 Scope Boundaries。
