## 已实现

1. `storyShelf` 和 `memoryPlacements` 在每次计算内建立书稿版本索引，按故事/档案取小集合，继续调用已有版本选择与校验逻辑。素材有效性用 Set 查询；摘要仍按原素材数组顺序选取，保留记忆 ID 顺序及重复值。
2. 云端 `storyCommand` 去掉未使用的写前全量房间读取。仍由服务端执行命令、校验权限和版本；成功后重新读取一次权威状态，失败仍抛错。本地模式继续读取状态再应用命令。
3. 加入 `[performance]` 控制台与实时日志：`room.load`、`room.cloud`、`story.shelf`、`book.refresh`。记录页面路径、耗时、成功/失败、条数；云端读取记录服务路径、降级原因、客户端分页请求次数。不记录正文、账号 ID、房间 ID、指纹或原始错误。日志 API 不可用时不影响加载。
4. `book.ts` 本地照片按 ID 去重、最多四张并行读取，同时开始读取云端插图列表。路径解析完毕后仍按原文顺序构建映射；缺失照片继续保留可恢复引用，所有读取结束后仍检查刷新序号、卸载、编辑中和选图状态。

索引只属于一次同步视图计算；没有跨页面缓存、没有更改指纹算法，也没有改动鉴权与迁移代码。

这次样本中的房间有 3 位成员、7 条记忆、23 个书稿版本；7 条故事记录中书架显示 2 本可用故事。

| 环节 | 房间云端读取 | 整页书稿 refresh |
|---|---|---|
| 编译后首页 | 8,004 ms | — |
