# 微信账号与拾光家忆账号关联

日期：2026-09-12

## 目标

让每个打开已上线小程序的微信用户自动获得一个稳定的拾光账号身份，同时继续使用该用户原有的云端人物、记忆和书稿，不新增登录表单，不采集微信昵称或头像。

## 实现

- 沿用微信云函数可信上下文中的 `OPENID`，客户端不能自行传入或冒充。
- `getOpenId` 在返回原有 `openid` 的同时，自动建立或刷新 `user_accounts` 账号记录。
- 对外使用 `account_<openid sha256 前 24 位>` 作为稳定账号 ID；数据库内部保留 `wxOpenId` 供服务端鉴权。
- `primaryFamilyId` 继续指向原有的 `family_<openid>`，因此不会搬迁或复制用户已有故事。
- 已存在的家庭空间会补记 `ownerAccountId`。新用户即使当时尚未创建家庭文档，也能通过账号记录找到主空间。
- 账号元数据写入失败时，`getOpenId` 仍返回原有身份，避免线上用户突然无法读取旧数据；下次启动会自动重试。

## 亲友邀请与共同记录

- 记忆之家的主人填写“怎么称呼对方”和“你们的关系”，生成带一次性小程序码的邀请图片。
- 好友长按识别小程序码，先查看邀请信息，再主动确认接受；邀请图片本身不授予任何数据权限。
- 邀请默认 7 天有效，只允许一个微信账号接受。同一微信重复打开保持幂等，其他微信无法接手已经接受的邀请。
- 接受后，该微信只获得指定记忆之家的 `contributor` 权限，不会看到邀请人的全部个人故事。
- 邀请卡中的称呼和关系成为好友在这个记忆之家中的成员信息；若好友尚未设置拾光称呼，也会用该称呼完成首次账号资料。以后在“我的”修改称呼时，会同步到其已加入的记忆之家。
- 亲友提交的文字以 `pending` 状态保存，确认前不会进入家庭时间线或正式书稿；当前不支持多人直接同时改正式书稿。
- 服务端只从云函数可信上下文读取 `OPENID`。客户端不能指定作者账号、成员身份或绕过邀请令牌。

## 邀请图片的使用方式

1. 主人在“记忆之家”点击“邀请亲友一起写”；
2. 填写称呼与关系，点击“生成邀请图片”；
3. 点击“发送邀请图片”，通过微信发给好友；
4. 好友长按图片识别小程序码，确认后进入对应记忆之家；
5. 好友点击“开始聊聊”，提交的故事会先等待主人公确认。

普通的小程序转发卡片同时作为兼容入口。正式版邀请图必须在新版本发布后重新生成；开发版、体验版生成的码只能由相应测试身份打开。

## 发布方式

这次需要同时部署 `getOpenId` 和新建的 `familyInvite` 云函数，并上传包含邀请页的小程序版本。只部署云函数不会让现有正式版出现邀请入口。

部署后应在云数据库确认：

1. 出现 `user_accounts` 集合；
2. 当前测试微信进入小程序后出现一条账号记录；
3. 记录的 `primaryFamilyId` 指向该微信原有 `families` 文档；
4. 出现 `family_invitations` 与 `family_access` 集合；
5. 两个测试微信可完成“生成邀请图 → 接受 → 进入指定记忆之家 → 投稿待确认”；
6. 原有人物、故事和书稿仍可正常读取。

## 边界

当前邀请只开放文字共同记录，不开放直接共同编辑正式书稿。图片仍按原有策略保存在各自手机本地，不通过邀请同步；线上 AI 处理仍需用户单独授权。
