# 故事完整链路：问题归纳、统一流程与整理记录

日期：2026-11-05。范围：记忆、写作、保存、图片、书架、发送与接收。

目标是保留现有功能、减少等待和重复逻辑，让后续修改可预测。不新增按钮，不删除用户资料，不将权限、历史版本或失败恢复当作无用功能删除。

## 历次问题归档

“已确认”指代码或既有记录能直接解释原因；不等于当前手机版本已验收。

| 用户遇到的问题 | 所属流程及证据 | 统一处理要求 |
| --- | --- | --- |
| 五张书页读不出文字，AI却继续聊天 | 材料读取；既有 OCR 修复记录 | 原件、读取状态、提取正文分开；未读到就不能声称读懂，不靠用户重复解释 |
| 不知道怎么写；反复被问已答过的问题 | 写作上下文；既有连续对话记录 | 从已有材料和对话提取目的，只追问确实缺失的信息；信息足够直接写 |
| 重开记忆后聊天、整理结果消失 | 会话与记忆关系；既有 session-continuity 记录 | 会话有稳定归属，未发草稿与已发消息分开；重开恢复同一会话 |
| 生成文章却仍停在保存记忆，找不到故事 | 记忆到故事的交接；既有 article-completion 记录 | 记忆独立保留，生成结果成为明确的章节，不要求重复存记忆 |
| 记忆和书脱节，不能查看来源或复用 | 来源关系；既有 memory-reuse 记录 | 章节保存 memoryIds；同一记忆可被多个章节使用；删书不删源记忆 |
| 改书名、章节名后，目录仍是旧名称 | 写入结果与显示投影；既有 title-directory-sync 记录 | 书架、目录、正文由同一已保存版本派生，不能分别维护名称和字数 |
| 退出提示本机保存，重开却看不到新稿 | 私人保存与外发审核混用；已确认，既有 private-save 记录 | 私人保存独立完成；分享检查属于分享流程；错误不能一律说是断网 |
| 分享的章节名、字数、正文不是最新 | 发送快照过期；既有 sharing-latest-version 记录 | 等待当前编辑保存确认，再取得同一 revisionId 的内容、标题和字数 |
| 有些书没删除入口，删除一直转圈 | 多入口行为及写后全量刷新；既有删除记录 | 所有适用书籍复用一个删除动作；确认删除结果后更新列表，不等全量历史 |
| Logo、输入框和面板产生大面积空白 | 编辑布局与固定预留空间；既有布局记录 | 装饰不占正文空白；编辑自然撑高；屏幕避让只由一个地方负责 |
| 最后一行看不到 | 文字高度、键盘、滚动定位；既有 last-line 记录 | 使用当前光标位置与原生输入高度，不把“滚到底”当作光标定位 |
| 中间按回车跳到末尾 | **本轮确认**：changeArticleText 按换行拆块，place 追加到末尾，组件强制 focus | 普通回车只修改当前文本；不换 blockId、不重建输入框、不随打印分页重建输入框或强制移动焦点 |
| AI回复后，已发文字还留在输入框 | **本轮确认**：问答成功后故意保留 xiaoyiAnswer 供后续整理 | 待发输入仅存草稿；已发送文字从聊天历史取。成功后清除对应草稿，失败保留，不能清掉后来输入的新句子 |
| 接收者看到开发版过期，发送者无法重发 | 发布渠道与邀请状态；既有 invitation-renewal 记录 | 区分开发版/体验版，未接受邀请可续发；上传、云函数更新和体验版选中是不同事实 |
| 接收后封面、图片、关联记忆丢失 | **已确认**：sharedRead 文字占位、copies 丢关联；上一轮已改，跨账号未验收 | 一次分享材料清单包含文字、封面、正文图、底图、关联记忆；原稿阅读与独立副本分开 |
| 文字图和实际文章不一致 | 多套输出内容；用户已要求删除文字图 | 保持已删除的文字图入口，不引入第二套内容替代现有故事 |
| 修一个问题反复补丁，测试多却仍不能用 | **已确认**：旧测试把拆段跳焦点、保留已发输入当作正确行为 | 验收以用户动作与结果为准；测试不能只证明旧实现还在运行 |

这些问题不能全部归因于一个 bug。共同的架构问题是：输入、草稿、保存回执、页面显示和分享快照的职责没有清楚分开；多条路径各自保存或读取一份状态，容易互相覆盖。图片读取慢还包含独立的逐张请求问题。具体页面是否仍有同类故障，需要逐条复现，不能凭归类宣布解决。

## 统一用户流程

```mermaid
flowchart LR
  A[提交材料或记录记忆] --> B[读取材料与连续对话]
  B --> C[结合已有目的生成故事]
  C --> D[编辑并自动保存章节]
  D --> E[保存确认后的书架与目录]
  E --> F[从已保存版本准备分享]
  F --> G[对方阅读获准原稿]
  G --> H[按现有操作保留为自己的书]
```

1. **材料和记忆**：保留原件与提取文本；文章使用稳定的记忆引用，不能靠书名猜关系。AI参考已读取材料和已有回答。
2. **输入与对话**：原生输入框负责光标和换行；数据模型记录输入，不能每次输入把整段重新塞回去。发送请求持有当时的文字快照；后续草稿不属于这个请求。对话记录承载已发文字，不再占用输入框。
3. **编辑与保存**：编辑缓冲区 → 本机恢复副本 → 带 requestId、expectedVersion 的云端写入 → 保存回执。异步回执只能确认它提交的版本，不能覆盖之后的输入。冲突保留两方内容；没有云确认不能宣称云保存成功。
4. **书架、目录和重开**：已保存 revision 是标题、正文、字数和章节关系的共同依据。列表可以投影，但不能另存一套可独立修改的标题。历史版本按需读取。旧格式兼容只发生在读取边界，不侵入每次输入。
5. **分享**：先完成待保存写入，再从同一保存版本准备现有发送入口；不能拿旧页面缓存作为最新内容。外发审核不阻断私人保存。权限检查保留在服务端，不能用客户端开关代替。
6. **接收**：原稿阅读显示获准原稿；“保留下来”生成独立副本，保留媒体、记忆及来源。不能为补封面覆盖接收者新增内容。老副本补齐、未完成的跨账号验收仍单独列出。

## 代码职责边界

| 职责 | 现有负责模块 | 约束 |
| --- | --- | --- |
| 当前输入、选择和原生高度 | article-editor、articleEditorLayout | 回车不拆块，输入不调用聚焦末尾，几何测量结果失效后不能回写 |
| 章节内容与版式 | articleModules | 保持块 ID；明确增删图片/块才改变结构；打印分页与编辑容器分离 |
| 保存及恢复 | articleService、draftRecovery、draftMerge | 保存回执与正在输入的稿分开；只合并有证据的增量，不吞掉失败 |
| AI对话 | xiaoyiCompanion、writingSession | 共用逻辑负责已发记录，宿主页负责归属；新输入不使上一条正常回复消失 |
| 记忆及书架读取 | roomRepository、cloudRoomStorage、storyBooks/flow | 按页面所需投影读取；查到规范记录即返回，仍兼容历史 ID |
| 图片解析与书籍装配 | bookImages、bookMedia | 单张和多张共用解析路径；普通照片批量读取；页面只决定是否需要等待图片 |
| 故事请求传输 | storyRequest | 共用请求封装和错误传播；具体版本、来源、保存回执校验仍在各业务模块 |
| 分享/接收材料 | sharedMaterials、copies、copyAssets | 同一事务复用同一份材料；跨存储 I/O 后必须重新校验，不用缓存绕过撤权 |

## 本轮实际修改与量化结果

- 删除回车自动拆块和强制 focus/cursor 逻辑。普通输入保留同一编辑容器，打印布局可独立分页；保留拖动、图片、已有布局和长文自然高度。
- 把旧格式的末尾换行处理限制在旧的无 blockId 记录；新编辑稿保留用户输入的换行，包括末尾空行。
- 问答成功后清除对应已发输入；网络/授权失败保留。用户继续输入时仍保留上一条回复和下一条草稿。使用原话/整理从已发历史读取，维持原有能力。
- 删除阅读页未使用的 readingLines 全文副本、无调用的 storyReceivePath、两个已无绑定的旧菜单方法和一个无用类型导入。
- 提取 bookMedia，移走书籍页面内图片读取和路径组装；合并发送、接收、导出的三套相同请求封装。
- 规范记忆查找：同一记录数据库读取 **3 → 1**；旧 ID 与跨账号校验保留。
- 九张本机缺失的普通照片：photoAccess 请求 **9 → 1**；按 ID 对应响应，拒绝的照片不串图，重复 ID 只读一次。
- 接收最终事务复用已加载的 materials；重复接收不再额外查找记忆作者。
- 编辑布局预先建立 blockId→文本映射，避免每个模块重复遍历全文。

这里的数字来自确定性调用次数测试，不是手机耗时测量，不据此声称响应快了几倍。

## 以后修复与验收的流程

每个问题先记录“从哪里进入、操作什么、应当得到什么、实际得到什么、对应客户端与云版本”。把同一状态链上的问题合并处理。先写能复现用户动作的测试，再删除错误规则或修正共同模块，不向页面追加绕行按钮。

| 完整场景 | 必须核对的结果 |
| --- | --- |
| 在长文中间回车、连续换行、中文输入、粘贴、再编辑末尾 | 光标留在编辑处，后文不跳走，末行可见；旧文/图片/手动布局保留 |
| 发一句话，等待时再写下一句；失败重试；关闭重开 | 已发记录不重复、不丢；成功清对应输入；下一句和失败草稿保留 |
| 修改书名/章节名/正文，立即退出，重开，再从目录分享 | 正文、目录、字数、分享采用正确保存版本；保存失败保留本机恢复稿 |
| 图片和记忆加入故事，重开，整书发送，另一账号保留再重开 | 封面、图文顺序、记忆关系完整；不同账号权限仍隔离 |
| 删除自建书/收到的书，取消删除或恢复 | 入口一致，无长期转圈，不删除源记忆或其他人的书 |

本地类型/回归通过只证明代码层检查。涉及键盘、焦点、跨账号接收时，还须用对应客户端走真实流程；没有真机或第二账号时记录未测，不填通过。冻结候选版本后只重跑受后续改动影响的场景，不反复做无关全量点击或付费 AI 调用。
