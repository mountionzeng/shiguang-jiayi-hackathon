# 先理清处境的对话体验版

2026-09-13。用户要求先在拾光小程序改一版自行试聊。

## 变化

`cloudfunctions/chatInterview/index.js` 的实际输出提示词允许先梳理客观处境、已知与待确认处，每轮最多一个问题，也允许不提问。取消每轮换维度、短回答自动转向内心和 50 字硬限制。根据具体证据与意愿逐步探索感受、联系和意义，保留来源与分歧，不代为核实、分享或解释他人动机。

响应 JSON 在完整解析后截取 text，上限从 80 字调至 240 字；提示词目标 40–160 字，最多 220 字。前文单条保留上限从 300 调至 500 字，与客户端单次输入上限一致，窗口仍为最近 16 条，未实现全量长期记忆。

- 没有变更模型、密钥、数据库、分享规则或客户端；已有客户端下一轮云端聊天即可使用。云端不可用时本地 fallback 仍是原来的追问逻辑。
- 未在真实用户故事中插入测试消息，实际语气和发现质量等待用户自行体验。

## 体验观察

用户是否先得到有依据的处境梳理；记不清或不愿展开时是否停止逼问；不同来源是否被并列保留；用户主动谈感受时是否顺势深入；是否还有无根据推断或强行升华。

本版没有读取亲友材料或实现共享事实网络，也不构成两端账号整合。另有邀请页面未提交修改，不属于此次改动。

## 试聊后修正：转向感受被误当成结束

用户截图显示：用户否定有新回忆、说明主要想谈感受，模型却回复“本身也是一种变化”“已经不容易”“等你想继续时再聊”。上一版“用户想停或暂不展开时不再追问”边界过宽，缺乏对否定对象的区分；去追问约束没有配套保持对话来回的要求。现有解析与 mock 测试无法验证模型对此语义的理解。

修正实际 system prompt：区分无新事件、拒绝一个方向和明确告别；主动谈感受时从前文具体线索提出一个好接的问题，不要求新事件，不空泛赞美，不自动收尾。明确告别仍不追问。增加虚构的搬家/踏实感正反例，不把用户私人经历写成训练示例。新增测试只验证生产提示词边界和上下文，不宣称证明模型质量。

体验验收：无新事件但想谈心情→继续；不知道怎么讲→搭具体话头；不谈某人但想谈自己→切换方向；今天先不聊→停止。也应检查旧版误收尾后继续发送能否重新接回。

修正版部署验收：188 项测试与类型检查通过。CLI 增量/完整部署均报 ResourceNotFound.Namespace（退出码仍为 0，不可当成功）；改用开发者工具原生右键“上传并部署：所有文件”完成 2 文件、7.2 KB 上传。随后通过 CLI 下载云端文件至临时目录，逐字节比对 index.js 与本地修正版完全一致，包含感受转向规则；SHA256 为 229bc34c2ca835c4ccfb8e6244f8b93c432518504819a08461999db21b608f81。已确认云端代码更新，未宣称真实模型语义测试通过，未插入用户故事或修改邀请页面。
